StitchCraft

Image to embroidery

Automatic digitizing makes a design that sews well from a picture of flat colours, such as a logo, clip art or a drawing, once it is traced into shapes. Settings on the shapes are optional. StitchCraft chooses the stitches of each shape by its width at the size it sews. A colour drawn under others sews what shows of it, and neighbouring shapes overlap where they meet. Specks and the background are left out, and the sewing is ordered for few colour changes and short jumps. Milestone M13 of the roadmap builds it, after M7.5. Photographs sewn in blended colours need another technique, outside the roadmap.

The flow

A picture becomes a machine file in 2 steps:

  1. In VectorCraft, place the picture, scale it to the size it will sew, and trace it with Object › Image Trace › Make.
  2. Run stitch export picture.vectorcraft --auto -o picture.pes --preview picture.png.

With VectorCraft installed, stitch export picture.png -o picture.pes takes both steps itself (below).

An Image Trace object is a group of the traced paths, with the source image hidden beside them (imageTrace.make in VectorCraft’s crates/engine, main at 0842941). stitch export already reads those paths, and Expand is optional. Without --auto it sews each of them as Ink/Stitch sews an SVG shape: every area as a tatami fill and every line as a running stitch, in paint order. In a test document of a traced square and a strip 2.1 mm wide beside it, both sewed as tatami fills. With --auto, each shape sews as this page describes. Once MC-8 confirms the rules on the machine, M13.8 makes automatic digitizing the default for VectorCraft documents, and --auto is then needed for SVG files only.

VectorCraft’s exporter plug-ins (P1, 0.14) move the second step into VectorCraft, as File › Export › Export As › PES, which StitchCraft’s formats are exporters for since M6.9. Their auto option is --auto. Since M13.7, StitchCraft’s Auto effect on the traced group says it in the document itself, with the rules’ settings in its dialog, and previews each path’s stitches: the document then sews digitized automatically from either step, without the switch.

An SVG file traced elsewhere, such as by Inkscape’s Trace Bitmap, sews the same way with stitch plan picture.svg --auto. Without the switch, an SVG file’s shapes sew as Ink/Stitch sews them, since the file may be one of Ink/Stitch’s.

What VectorCraft does and what StitchCraft does

The 2 programs split the work. VectorCraft’s Image Trace (its crates/trace) already does what a picture needs before it is embroidered:

  • Its colour modes reduce the picture to a few flat colours. Its Document Library palette traces with a swatch library’s colours exactly.
  • Its Noise setting leaves out areas smaller than a number of pixels, and Ignore White leaves out white areas.
  • Its Abutting method traces each colour’s areas as paths that share their edges with their neighbours.
  • Create Strokes traces lines up to its Stroke width as stroked centre lines.
  • The paths are smooth curves over the steps of the pixels.

StitchCraft links none of VectorCraft’s crates (integration), and a tracer of its own would repeat VectorCraft’s. StitchCraft does the embroidery. It chooses the stitches of each shape, the overlaps between shapes and the order they sew in.

stitch palette (M13.7) writes a machine profile’s thread palette as a GIMP palette file (.gpl). VectorCraft loads that file as a swatch library (Window › Swatch Libraries › Other Library…), and Image Trace’s Document Library palette then traces the picture in the threads’ colours.

Automatic elements

An automatic element is a shape whose stitches StitchCraft chooses. The readers make one of:

  • each object of a VectorCraft document that has no StitchCraft effect, with --auto;
  • each path with the StitchCraft Auto effect, on the path itself or on a group or a layer around it, with or without --auto (M13.7, REQ-VC-016). A path nearer to a StitchCraft stitch effect, its own or a group’s, sews as that says. The effect’s parameters are the shape’s settings of the rules (below). A stitch effect says how an object sews, so an Auto effect beside one isn’t used, and SC-W0807 says so;
  • each SVG element without inkstitch: settings, with --auto.

An element with settings is not digitized automatically, whether or not the switch is given: it sews as its settings say, as far as its reader reads them. So a picture can be digitized automatically and one of its shapes then set by hand. A shape’s fill gives its area and its stroke gives its line, each with its thread, width, join and cap, as for any element. A trim or a stop that an Ink/Stitch command asks for is not a setting of the stitches, and an automatic element keeps it. An element sewn as several elements keeps it for the last of them. Start and end positions, from Ink/Stitch’s commands or VectorCraft’s markers, and a target point, are not kept: automatic digitizing places where its parts start and end, and the readers say the commands and markers aren’t used (REQ-GEN-001). The elements it makes have none. An automatic element’s clip paths are applied before it is digitized, where an ordinary element’s are applied as it is generated: the shape digitized is what its clips leave of it, and its columns follow what shows (REQ-GEN-005, auto/clips.rs). A line’s cut end takes the line’s cap. A shape wholly outside its clips is left out (SC-W0013).

The readers mark the element (Element::automatic), and they read the switch from Reading, which every host takes. Before anything is generated, the engine turns each automatic element into ordinary elements whose settings say what to sew (stitchcraft_engine::auto). The generators, the assembly and every host then treat them as shapes set by hand. SC-I0901 counts the shapes digitized, by the stitches they sew as. An automatic line sewn across its width follows the drawing, and the reader names what the drawing draws across the line that its stitches don’t follow (REQ-AUTO-005). Of a VectorCraft document, that is the line’s alignment inside or outside a closed path and its width profile (SC-W0807). Of an SVG file, it is transforms that stretch the line more one way than the other (SC-W0802). Under such transforms a viewer draws it wider one way, and its stitches are as wide as the transforms stretch it on average. Its caps are followed (below), and so are its corners, joined as the drawing joins them. An SVG join that is not set is SVG’s miter, limited by stroke-miterlimit, where Ink/Stitch reads a miter limited at 5.

Digitizing doesn’t add an error of its own (REQ-AUTO-006). A part that its width’s stitches cannot sew is sewn otherwise, or left out with a warning, and a shape that paints nothing sews as it would without the switch. One odd shape among hundreds never keeps a design from being written.

Which stitch a shape gets

Automatic digitizing chooses the stitches of each part of a shape from the part’s geometry alone, by the first rule of one table that the part matches (M13.21, REQ-AUTO-030). The picture’s subject is no input of a rule, and a flower and a dog go by the same table. A part is a connected piece of what shows of an area, once the layers are flattened and the specks are merged (Neighbours).

Width alone chose the stitch before. A blob as wide as a satin column then sewed as a column bent into its corners, and a ragged patch of a traced photo as several columns that fan where they meet. On the traced running dog, 62 of 107 shapes sewed so.

The measures

  • Widest. The diameter of the largest circle that fits inside the part. The rules use one fact about it, whether a circle as wide as a bound fits.
  • Width. The diameter of the circles that fit inside the part centred on its centre lines, averaged along them (width along the line).
  • Slenderness. The part’s area divided by its width squared, which says how long it is for its width. A rectangle 3 by 9 mm measures 3, a disc 0.8, and a letter drawn with an even stroke 6 or more.
  • Unevenness. How much the width varies along the lines: its standard deviation divided by the width. The letters of a drawn patch measure 0.11 to 0.23, and the ragged patches of 4 traced photos 0.39 to 0.52 at the median.
  • Lines. How many centre lines the part has. A part of one line has no branch.
  • Reach. How far the part lies from one of its centre lines on both sides of the line, in radii of the widest circle that fits inside it centred on its lines. A column has 2 rails, the part’s outline on either side of its line. Each rail is measured by its farthest corner beside the line, and a column by the nearer of its rails. A part measures what its farthest column does. However its width tapers, a column measures 1, and a star measures 1.6 to 2.6.

The rules

The rules’ table is generated from the code’s own (stitchcraft_engine::auto::rules::RULES), with each bound’s default, so that the table, the notice a shape gives and the tests at each bound can’t drift apart. The rules are tried in this order. First a shape whose setting names a stitch sews so. Then a speck merges into a neighbour and a line runs. A ragged thin line has merged into its neighbour before the rules are tried (Neighbours). Areas are filled next, with compact parts and uneven parts after them, and then a part with arms. Any other part sews as satin columns, unless its columns are refused. One function compares every bound (auto::rules::choose), a length to the micrometre and a ratio to its third decimal. A width written in another unit that converts to a bound give or take a rounding error, such as 7 mm in CSS pixels, is that bound.

A compact part is filled (REQ-AUTO-031) because a blob has no way to run. Its centre line is what its corners leave of its middle, so a column along that line sews stitches of unlike lengths round a point. A fill sews rows across the blob at the design’s angle. On a part under 7 mm wide a row is a stitch or 2. The fill then looks like a satin column without the fan. A dot is the smallest compact part.

An uneven part is filled (REQ-AUTO-032) for what its columns would do: a part of several lines sews a column along each, and the columns meet at its junctions. Where the strokes are even, as a letter’s are, the columns meet cleanly. Where the width swells and shrinks, each column fans at its ends and the outline sews scalloped. A part of one line isn’t held to its evenness: a leaf and a tapering stroke narrow smoothly, and one satin column sews each well. A piece of an uneven part that is narrower than the narrowest satin stroke leaves the fill, cut as a narrow part of a broad one is (Shapes in parts), and sews as a line. The measure is of the whole part, so a letter of a thick and a thin stroke is uneven too, though each stroke is even. A design drawn in such strokes turns the rule off, which the logo style does.

A part with arms is filled (REQ-AUTO-050, M13.27). A star of 4 points 5 mm across has 2 axes, and its centre lines keep one of them. The points of the other axis are short for the star’s middle, so they are left out of the lines as bumps, as the corner of a sharp turn is (centre lines). Such a star counted one line, 0.97 mm wide and 7.5 times as slender, which is neither compact nor uneven. It sewed as one satin column from point to point, with its 2 other points as bumps on the column’s sides. This measure tells such a part from a column. The points left out lie on both rails, far from the line. A column’s rails lie no farther from its line than the radius of its widest circle. A part that measures more than 1.4 is filled. The corner of a sharp turn lies on one rail only. A letter V measures under 1, and keeps its columns. The rule comes after the uneven one, so a part that was filled before is filled by the same rule as before, and only columns moved.

2 other measures were tried first. Counting the points left out as centre lines makes a star uneven, but a letter V 4 mm tall varies by 0.29 of its width, 0.01 under that rule’s bound. Measured on one side alone, or as the longest stitch for the line’s length, a sharp corner counts as a star’s point does. The rule has 2 limits. A star of 3 points measures 0.87, since its third point lies on one rail as a corner does, and stays a column. A star nowhere wider than the narrowest satin stroke is a line before its columns are looked for.

Holes (REQ-AUTO-033). A part that is filled is filled whole under the areas that fill its holes, and they sew on it (Layers). A dog’s nose sews as one fill with the nostrils on it, where it sewed as 4 columns round them. A hole that nothing fills is left open, and a part sewn as columns keeps its holes, as a ring or a letter’s counter does.

What leaves a fill (REQ-AUTO-034). A piece of an area leaves the fill only where it is narrower than the narrowest piece of a fill, and only when the rules make it a line or a column. A balloon’s string leaves the balloon, and a wing 6 mm wide stays in the fill.

Refused columns (REQ-AUTO-035). A satin stitch longer than the widest satin column lies loose, and a column no wider than that on average still sews one where its rails part, at a corner or round a bend. A column’s longest stitch lies between the 2 points as far along its rails, as shares of their lengths from one rung to the next, at a corner of either rail. A part with a column that would sew a longer one is filled, and SC-I0902 gives the stitch’s length. The widest satin column is the longest satin stitch a machine sews well, so a shape may set it lower and never higher. It is the same for every machine profile so far, and becomes a value of the profile with the step that splits the stitches of a wider column.

Seeing and changing the choice

SC-I0912 says, for each part of a shape, which rule it sewed by and the measures that decided it (REQ-AUTO-036). The settings come in 3 tiers (Settings):

  • A shape names its stitch with auto_stitch. A part that can’t sew so goes by the table.
  • A design leans the rules towards satin columns or fills with auto_prefer, which moves 3 bounds together. auto_fill_uneven turns the filling of uneven parts off, and auto_fill_angle gives every fill one angle.
  • The bounds themselves are advanced settings. No dialog shows them, and stitch plan --set sets one on every shape digitized automatically, unless the shape sets it.

A style is a named set of values of these settings, and no rule of its own: stitch plan --style logo for flat art drawn in strokes, and --style photo for a traced photo, which is the defaults.

The grounds of the bounds

The narrowest and the widest satin column are established: digitizing manuals put the narrowest satin at 1 to 1.5 mm, and split a satin stitch at 7 mm to keep its look. The least slenderness, the most a width varies and the narrowest piece of a fill are StitchCraft’s own. Their values come from measurements of 9 pictures, which are 2 traced dogs, 2 traced photos, a pear, 3 emblems and a lettered patch, whose letters all kept their columns. Between a slenderness of 2 and 4 the running dog’s result moves by 7 shapes of 107. The bound of a part with arms, 1.4, lies between what was measured on 2026-11-15. Drawn bands, leaves, crosses and letters measure at most 1.0, the lettered patch’s letters at most 1.19, and the dogs’ parts that sew as columns at most 1.23. Drawn stars of 4, 5 and 6 points measure 1.61 to 2.62, and 5 blobs of the dogs’ fur 1.51 to 2.11. MC-8 confirms the defaults or changes them.

Stitch types by width

An automatic element is measured at the size it sews, in millimetres (REQ-AUTO-002). Its width at a place is the diameter of the largest circle that fits inside it there. This section says how each stitch is made once the rules have chosen it.

A stroke is a line as wide as it is drawn (M13.1):

  • No wider than min_satin_stroke_width_mm it sews as a running stitch along its path (REQ-AUTO-002), tripled from 0.5 mm wide (below). A satin column that narrow is too narrow to stitch across (REQ-SAT-015), so the bound is the same.

  • Up to 7 mm it sews as a satin column as wide as its stroke, with its path as the column’s centre line, as a satin column drawn as one path does (REQ-SAT-016, REQ-AUTO-003). A centre line is one subpath, so a stroke of several sews a column for each, in order. The second and later columns are named after the stroke with #2, #3 and so on. A traced line’s ends are round or square, and its caps are part of the line drawn. An open end with a round or square cap reaches half the stroke’s width past the path’s end, straight on, as far as the cap does. A round cap’s end is then square, which covers its corners too. A column cannot follow a subpath that turns more tightly than the stroke is wide, such as a small ring traced from a dot. Nor can it follow a subpath shorter than a CSS pixel. Its rails would fold over themselves, or vanish. The rails the satin column would make tell whether it can follow a subpath. A subpath it cannot follow sews as the area it paints, filled as a wider line is (SC-I0902). So does a dot that a round or square cap draws. A dot with a butt cap draws nothing, and is left out (SC-W0401).

  • Wider than that, the area it paints is filled (REQ-AUTO-004). That area is each segment widened by half the stroke’s width to each side, with its corners joined as the stroke’s join joins them and its open ends capped with its cap. It is the stroke’s area within the shapes’ tolerance. A miter longer than its limit is cut square. Those pieces, joined into one area, are the fill’s outline. A part of it smaller than 1 mm² is a speck, merged into a neighbour or left out as specks are (Neighbours). An area that would reach more than 10 m from the origin is left out (SC-W0903). No design lies there.

    The pieces are not handed to the area code one by one, which would cost many times the work of their outline. Each open subpath is one ring instead. It follows the right side forward, the end cap, the left side back and the start cap. The outer side goes round each join, and the inner side goes in to the path’s point and out again. A closed subpath is 2 rings, one for each side. Such rings wind round each point as many times as the pieces cover it. The nonzero rule then fills exactly the pieces’ union. A line of more than 32 chords is cut into lengths of 32 chords. Each length is a ring made into its area alone, and the areas are then joined. A 10 mm line a metre long fills within the default budget that way.

Triple runs (M13.4, REQ-AUTO-015). A running stitch that automatic digitizing makes is a triple run from 0.5 mm wide: each stitch is sewn 3 times, bean stitch 1. A running stitch sewn once is as fine as the thread, and a line drawn half a millimetre wide or wider sews bolder tripled. A stroke is as wide as it is drawn, and a narrow part (below) as wide as the circles that fit inside it along the middle. Widths are compared to the micrometre, and MC-8 confirms or changes the bound.

Every automatic satin column, a stroke’s as well as a shape’s, has the settings of its width (M13.5, below). A shape’s area is a tatami fill apart from its narrow parts (M13.4), its parts as wide as a satin column (M13.5) and the narrow parts of its broad ones (M13.6).

Narrow parts (M13.4, REQ-AUTO-013). A part of a shape that is narrower than min_satin_stroke_width_mm everywhere sews as a running stitch along its centre line, as a stroke that narrow does. No circle that wide fits inside such a part: shrunk by half the width with the polygon buffer of M5.7, nothing of it is left. The width is taken half a micrometre wider, so that a part as wide as the bound, give or take a rounding error, is narrow, as a stroke is. Before that, a part smaller than 1 mm² is a speck (Neighbours), and stays in the area. So does a part whose centre line has no length, a dot.

  • What sews. The rest of the shape is a tatami fill, and each narrow part’s line sews after it, in the order of the parts. It is named after the shape with #2, #3 and so on, or with the shape’s own name when nothing of it is filled. A trim or a stop after the shape follows its last part.
  • Its width. A part’s width at a point of its centre line is the diameter of the largest circle centred there that fits inside it. Averaged along the line, leaving out the piece that runs on into a tip’s corner, it says whether the part is a triple run (centre lines). A strip as wide all along as a stroke is as wide as the stroke.
  • To its neighbours a narrow part’s line paints the part. It sews after a fill it borders. An area sewn before it reaches under it, and is cut away under the part where the part covers it, as under an area (Neighbours).
  • Once the layers are flattened. A shape’s parts are found in what it sews once the layers are flattened (Neighbours): what shows of it, with the holes its details fill closed. A stacked trace’s dark outline under the colours inside it shows as a ring, and sews as lines and columns, as an abutting trace’s outline does. A broad area’s holes under its details are closed, so the strips of it between the details are part of its fill. The parts are found before specks merge and before each area reaches under its neighbours.
  • SC-I0901 counts a shape whose every part runs as a running stitch, and any other as a tatami fill. Finding a part’s width and centre line is part of the work of digitizing its shape. A part whose width or centre line can’t be found, a bug, stays in the fill, and SC-E0009 names its shape.

Parts as wide as a satin column (M13.5, REQ-AUTO-016 to REQ-AUTO-018). Filled, a part as wide as a satin column sews rows no longer than it is wide wherever they cross it. A digitizer sews it as satin columns along its strips and round its rings. A part that isn’t narrow, and is nowhere wider than 7 mm, is as wide as a satin column. Shrunk by 3.5 mm, taken half a micrometre wider, nothing of it is left. Such a part sews a satin column along each of its centre lines, between its own outlines (centre lines):

  • Its columns. Each line sews one column over the triangles round it. A line is cut where it turns by more than 60°, so that the column before a corner covers it and the one after ends under it, as an arm of a T ends under its bar. A branch of the line is a column of its own however short, as each arm of a t’s crossbar is. A branch to the second sharp corner of an end is a bump instead, sewn with the column beside it. So is a tooth, a step of a traced outline as narrow as the narrowest satin stroke somewhere and no longer than its junction is wide. A column of its own, it would sew a short line beside the column and cut that column in 2. A column’s rails are the part’s outline on either side, and its rungs lie square to it.
  • Their ends. A column that ends where another runs on ends under it: it sews first, and is 0.4 mm longer at that end, its pull compensation, by its push compensation, so that no fabric shows where they meet. Otherwise a column ends at its farthest point along its line, flat along the end’s edge when that lies within 20° of square to the column, and at a point otherwise.
  • Their order. A column that ends under another sews before it. Then the longest sews first, and each next column is the one with an end nearest where the last one ended, sewn from that end. A ring starts at its rung nearest. Where the columns that end under each other go round, as a pinwheel’s bars do, the first in that order sews first, and the last ends on top of it.
  • Their width. A column is as wide as the circles that fit inside the part along its line, as a narrow part is, without the piece of its line into a tip’s corner. One no wider than the design’s narrowest satin stroke runs along its line as a triple run, unless the column is wider than that stroke somewhere along its line, but at its 2 ends, or reaches farther than that from its line beside it. Both are measured inside the column’s own outline, the triangles round its line. A running stitch covers a thread’s width along its line, so where the column is wider, the fabric beside the line shows unless an area sewn before it reaches under it. Measured on average alone, the strands of fur in the owner’s traced dog that widened at an end ran, and so did its small blobs, each beside other lines, and they left fabric bare. So did a column whose line ran along one side of a bump 1.4 mm across: the bump’s triangles were the column’s, far from its line. Where 2 strokes meet, the part is wider than either, by where the junction’s triangle has its corners. Measured inside the part, the circle at the junction of a T in strokes 0.9 mm wide was up to 1.13 mm, and the T’s bar sewed as a satin column one way round and as a triple run mirrored. A column’s own outline crosses to the other column there. A line’s end lies where it meets another line or runs into a corner, and measures that. On TS-13B, the outer legs of the M 4 mm tall, 0.81 mm wide on average, are 1.05 mm wide where the M’s middle strokes meet them, inside their own outlines, and sew as satin columns.
  • A dot. A part whose every line is shorter than half its width along it is a dot, and stays in the fill, as a part whose line has no length does. A disc or a square has no way to run, and its lines are only what its triangles leave of its middle. Its corners lie on one circle, where the triangulation ties, and how each tie breaks depends on where the part lies and how it is drawn. Without the rule, of 2 dots alike one could sew a column across and the other a fill. A disc’s or a square’s lines are 0.4 times as long as it is wide, and discs and squares no wider than a satin column are fills wherever they lie. A rectangle 3 mm wide is a column from 3.5 mm long.
  • What sews. The columns sew after the rest of the shape’s area, named as a narrow part’s lines are, and paint the part to its neighbours. SC-I0901 counts a shape as satin columns when none of it is filled and one of its parts sews a satin column.
  • Drawn. Each column is drawn with its rails and rungs, as the Stroke to Satin filter draws one, and read back it must give them. A part whose triangles don’t make a column round one of its lines, or one of whose columns is read otherwise, stays in the fill, and SC-I0902 says so. A rung added to tell a column’s rails from its rungs goes across an end that doesn’t reach under another column where one can take it (satin columns).

Shapes in parts (M13.6, REQ-AUTO-019). A shape wider than 7 mm in places and narrower in others sews in parts. Its broad parts are a tatami fill, and its narrow parts sew over the fill as lines and columns, as a digitizer sews a balloon’s string over the balloon:

  • Its broad parts are what an opening with a disc 7 mm across leaves: the shape shrunk by 3.5 mm and grown back by 3.5 mm, with the polygon buffer of M5.7, each taken half a micrometre wider, as the bound is. An opening finds them without the shape’s centre lines.
  • Its narrow parts are the rest of the shape, cut where they meet the broad parts. The opening rounds each convex corner of a broad part, and leaves the corner as a narrow part. A narrow part that reaches less than 1 mm² beyond 3.5 mm from the broad parts is such a corner, or a stub too short for a column, and stays in the fill, as a speck does. Length along its centre line tells no corner. The piece a square corner leaves has a horn along each side of the corner, and its centre line runs 6 mm along them, less than half a millimetre wide.
  • The cut. Where a narrow part meets a broad one, the opening leaves an arc, and a column would end there in a point at one of its corners. Each narrow part is cut square there instead, at a chord across it square to the way its sides run on, from the end of the arc that lies farther along that way. What lies past the chord goes to the fill. A chord that would cross the outline of the piece or of the part is left out, and the arc stays. That holds a hair from the chord’s end too. Where an arc ended 2.5e-10 mm before a corner of a traced cat’s ear, the chord crossed the edge after the corner, and the piece had no triangulation (M13.23). A column ends flat along the cut, however long it is, so that a star’s points end along the star’s middle. The triangles that touch the cut are the column’s end, and its line stops where they start (centre lines).
  • What sews. Each narrow part sews as a part of its own. One narrower than min_satin_stroke_width_mm everywhere runs along its centre line, and one no wider than 7 mm sews as satin columns. Any other stays in the fill. The fill is the shape without its narrow parts. It sews first, and reaches the overlap, 1 mm, under the lines and columns sewn over it (Neighbours).

Centre lines. A narrow part’s centre line, its width along it and the rungs across it come from a constrained Delaunay triangulation of its outline, with points added along its long edges so that no triangle is much longer than the part is wide:

  • Each edge of a triangle that lies inside the part is a chord across it, as long as the part is wide there.
  • A triangle with 2 inside edges is part of a strip, and its inside edges are the strip’s rungs.
  • A triangle with 3 inside edges is a junction, where 3 strips meet, and one with 1 is an end.

The centre line joins the middles of the chords (M13.4, REQ-AUTO-014). A round end stops it about half its width from the end, on its middle, and a sharp point draws it on to the point. The small bumps of a traced outline, and the corner past a sharp turn, would branch it, and are left out. A branch longer than its junction is wide is an arm, and has a line, as each arm of a small T’s bar has. At each junction left, the 2 branches that run on most nearly straight are one line and the third ends there, and a ring has a closed line. No piece of the line is sewn twice. A part’s lines sew one after another, the longest first, each from its end nearest where the last one ended. The centre lines page has the rules in full.

A part as wide as a satin column sews a column along each of its lines (M13.5, above). Its rails are the part’s outline on either side, and its rungs come from the triangles across it. A junction joins the 2 lines that run on most nearly straight, and the column of the third ends under theirs. A ring, such as a letter O, is a closed column between its outer and inner outlines. The satin generator sews these columns as it sews columns drawn with rails and rungs.

A filled area keeps a hole as its rows stop at its edge.

Letters sewn as strokes

Block letters and a logo’s bars are drawn in strokes: straight bands of nearly even width that meet at joins. An embroidery font sews each stroke as a satin column of its own, its stitches across it. The columns along a part’s centre lines run on round the corners where strokes meet. An M’s middle strokes took in the corners of its stems there, their rails ran on unevenly, and their stitches leaned up to 56°. TS-13B said so 6 times (SC-W0208). A part that reads as strokes now sews a column along each (REQ-AUTO-087), and where 2 strokes meet one runs through and the other stops (REQ-AUTO-088). The code is normalize/strips/strokes.rs and its joins strokes/joins.rs, called from auto/columns.rs.

Reading the strokes. Each ring of the part is cut into straight runs, from its sharpest corner: a run’s points lie within 0.05 mm of the line between its ends. 2 runs are a stroke’s sides when all of these hold. They run opposite ways within 5°, and lie as far apart at both ends within a tenth. They are at least the narrowest satin stroke and at most the widest satin column apart, and overlap along each other by half that width. The longer is as long as the width and the shorter half as long. The part fills the band between them but for 2 % of it. Sides on the same 2 lines, within 2° and a tenth of the width, are one stroke, as an E’s stem is between its arms.

Joins. 2 strokes meet where their bands, a width longer at each end, share more of the part than 0.02 of their widths’ product (0.01 mm² at least). A stroke runs through when the part goes on past the join by half its width both ways along it. Of 2 that both do, as in a cross, the longer runs through and the other loses its band, narrowed on each side by its stitches’ reach across, and sews in 2 columns. Of 2 that end there, the one whose end lies more nearly square to it runs through, by more than 0.15 of its width. An M’s stem has a square top and runs through, and its middle stroke, cut on the slant, stops. Alike, 2 strokes whose lines meet between 15° and 60° are cut along the line that halves the angle between them, as at the top of an A and the bottom of an M’s V, and each reaches max(0, reach / 2 - reach cos) past that line. There, reach is the stroke’s pull compensation and cos the cosine of its line to the halving line. At a blunter join, as at an L’s corner, the longer runs through. Cut along a halving line there, each would end in a point at the corner’s outside, and the 2 tips and their pull compensation piled 4.34 fills on TS-13D’s white frame, where the columns along their centre lines laid 4.17.

Where a stroke stops. A stroke that stops keeps its side of the other’s near side, moved into the other by reach (1 - cos), the cosine of the angle between the 2 lines: its own stitches’ pull compensation already reaches the rest across the line where they meet. That stub is part of the stroke’s end when it lies within the flat end’s 20° along the stroke, and it does for a stroke wider than reach / tan 20°, 1.1 mm at the default 0.4 mm. A wider stroke then ends on the other’s side, and the overlap is the other’s own pull compensation, whose stitches run along the stopping stroke at a square join and reach 0.4 mm past that side. Restored as rails of the stroke, the stub made TS-13D 4.55 fills thick where it is 4.23, the lettered patch 4.09 where it is 4.00 and TS-13B 3.90 where it is 3.85, and no measure showed a gap either way, so the stub is left out until a sew-out shows fabric where 2 strokes meet (MC-8). The stroke that stops sews first, and ends under the other without a push compensation.

Columns. Each stroke’s piece is the part inside its band, cut so. The pieces must cover the part but for 1 % of it. A piece’s rails are its 2 sides from its end least far along the stroke to its end farthest. An end whose points lie within tan 20° of the width along the stroke is flat, and any other ends in a point, as a column ends along an edge within 20° of square (REQ-AUTO-016). A rung lies square to the stroke at every corner of either rail. A flat end on the slant gets one more, past its corner farther in by twice the corners’ spread along the stroke, so that the stitches between pair no more than 1.5 of one rail with 1 of the other. A rung 0.1 mm past the corner notched the A’s feet. The middle line has a point every half width, so that a stroke’s thin tips measure as the centre lines’ do. A piece’s points within 0.001 mm of a corner of the part are that corner, so that a rail runs along a hole’s edge where the hole does (REQ-AUTO-084): without that the A’s counter fell to 7 %.

When a part keeps its centre lines’ columns. The rule runs only on a part that wasn’t cut from a broad one and reads as 2 strokes or more that meet. Its centre lines must give 2 columns or more, none of them a ring. Its columns are kept only when none of them runs (REQ-AUTO-016). Strokes are straight only: a curved stroke, as a C’s or an S’s, or a D’s bowl, keeps today’s columns, and curved strokes are a candidate for a later step.

Measuring the lean. A stitch leans by the angle between it and the square to its stroke, over the zigzag top stitches 0.4 mm long or more, leaving out the 2 at each end of a column. Those follow the column’s end. A flat end 19° on the slant measured 31° with the zigzag’s own 10° at 6 mm, which says nothing of how the column lies along its stroke.

Neighbours

The shapes of a traced picture meet. VectorCraft’s Abutting method traces each area with a hole where the next one lies, and its Overlapping method, like Inkscape’s Trace Bitmap with its Stack option, traces each colour whole, over the colours under it. Sewn as drawn, either sews badly where shapes meet, and digitizing mends it in 5 steps, in this order (stitchcraft_engine::auto::neighbours, M13.2, M13.12 and M13.18).

  1. Background (REQ-AUTO-009). The lowest shape is the picture’s background when it is an automatic area with a shape on another path drawn on it, and its outlines cover the box around the design to within 0.5 mm of each side, its holes and notches aside. The box is the one around the defining points of every shape’s path, the background’s own included. So a disc in the corner of a square, lowest but covering less of the box, is part of the picture. A shape on its own path is the same object’s: the readers make a fill and its stroke 2 elements on one path, and a design of one shape with a stroke sews it. Where a shape of a tightly cropped picture touches its edge, the Abutting method cuts a notch in the background instead of a hole. A part of the box its outlines leave is a notch when the areas drawn on it fill it, to within twice the shapes’ tolerance, and it runs along the outlines at least as far as along the box’s sides, measured 0.5 mm inside them. A part that runs further along the sides is no notch. A disc or a rounded square that reaches the sides leaves such parts in its corners, and sews as the picture, though the shapes in its corners fill the rest. The cost of this rule is a background cut away along a whole side, by a bar down the side say, or cut in two by a band from side to side, which is sewn. The background is left out with SC-W0906 before anything is digitized. With a StitchCraft effect, it sews as that effect says. Finding it has the work budget to itself, and a background that needs more is sewn, which SC-W0906 says. What shows of the background inside the picture once the layers are flattened (step 2) is sewn: its parts that come no nearer than 0.5 mm to the box’s sides. A trace that stacks its colours draws the background whole under the picture, a white disc on a badge included, which a trace whose colours abut draws as a shape of its own. Such a part sews as the background’s own area, and SC-W0906 counts it.

  2. Layers (REQ-AUTO-023, M13.12). Digitized as drawn, a stacked colour’s stitches would be chosen for its whole shape, though most of it is hidden. Taken as it shows, a broad area with details on it splits into narrow columns between them, traced either way, as a flower’s middle does round its dots. A digitizer fills such an area whole and sews the details on top. So before anything is digitized, the layers are flattened, in 3 parts (auto::neighbours::layers).

    • What shows. The automatic areas drawn after an area are taken from it where they overlap it by more than twice the shapes’ tolerance, as the order measures an overlap (Sewing order). Rounding leaves hairlines where edges drawn as one meet, as round a disc drawn a hair larger than the disc on it. A part of what is left that is narrower than twice the shapes’ tolerance everywhere, measured as a narrow part is, is such a hairline and is dropped. An area that they cover whole sews nothing (SC-I0904), and so does one of which only hairlines are left.
    • Details. Where what shows of an area is wider than its widest satin column somewhere (auto_max_satin_width_mm), the area is digitized whole under its details, the automatic areas that fill one of its holes. They fill the hole when what they leave of it is no wider than twice the shapes’ tolerance, or smaller than the area’s smallest area. The hole is closed, and the area’s stitches are chosen by its width with the hole closed (Stitch types by width). An area, or a part of one, no wider than a satin column everywhere, such as a letter or an outline, keeps its holes, and the shapes in them sew beside it. Closed, it would be a broad fill under them. Specks in a hole aren’t details. When only specks fill a hole, the hole is left open, and the specks merge into the area round them (step 4), which closes it. A hole is filled from the parts whose boxes meet its own, and costs the work of those parts alone.
    • Moved back. The area sews before its details, so that they lie on it. It moves back in paint order past them, past the automatic areas whose part that shows doesn’t overlap it, and past the other shapes whose boxes don’t come within twice the shapes’ tolerance of its box. It never moves across a stop, nor when it has a stop after it. The areas move the largest first, so that an area moves before the areas inside it. Once all have moved, a hole whose details don’t all sew after its area is left open: sewn after them, the area would cover them. The area couldn’t move back past them, or another area that has one of them for a detail moved back past it. On a red square with a white ring on it and the red showing again as a bullseye in the ring’s hole, the ring moves back before the red, the bullseye being its detail, and the red’s hole is opened again round the ring.

    The overlaps (step 5) then cut the area away under its details, the overlap inside their edges. So a trace that stacks its colours sews as one whose colours abut. An area whose region changed is given its new outline, and one whose region is what it was keeps its path as drawn. SC-I0908 counts the areas that sew only what shows of them and those digitized whole under their details.

    Each area has the work budget to itself at each step of the flattening, and again when it is given what it sews. It costs a unit for each shape and each part it looks past, and the work of those near it. An area that needs more work for a step does without it. One that needs more to find what shows of it is sewn as it is drawn, in its place, but for the background, which is left out whole. The other areas’ holes are found without it. When finding an area’s details needs more work, its holes are kept open. When its move does, it keeps its place, and the holes whose details then sew before it are opened again. When giving it its region does, it is sewn as it is drawn, and isn’t counted as digitized whole. SC-I0908 names each. SC-E0009 names an area whose region the region code fails to join, a bug, which is treated the same way.

    The test pictures (Testing) sew alike traced either way. An emblem 60 mm wide, a navy square with a white disc, a red star on the disc and 3 gold bars, on white, sews the same shapes with each thread. The navy square is one tatami fill of 1,848.5 mm², sewn first. The white disc is one fill of 380.7 mm² as its layers are flattened, sewn after it: the disc’s 531 mm² less the star, which it then reaches under. The bars sew as satin columns 3.00 mm wide, as drawn, and the star as one fill. The stitches of the 2 traces differ by about 1 %, because the traces draw their colours in different orders. A button, a yellow disc 24 mm across with 7 orange dots in a black rim 2.5 mm wide, sews the same shapes with each thread either way, and as many stitches, 1,925, 1,845 of them in the same places. Its yellow is one fill of 445.9 mm² under the dots, each dot a fill too, and its rim a satin column 2.50 mm wide. tests/auto_pictures.rs keeps the pictures sewing so.

  3. Thin lines (REQ-AUTO-090, M13.18). A trace of a photo draws soft shading and the strands of fur as thin lines between patches. Each sewed as a running stitch between 2 fills, which ended their rows on it: the traced dogs sewed 15 to 34 shapes so, and those lines caused most of their stitches astray, their slivers and their jump threads. A digitizer sews such a strand as part of the patch it lies in. So once the layers are flattened, and before the stitches of any area are chosen, a part of an automatic area that is narrower than the narrowest satin stroke everywhere, and is no speck, is a thin line when its width varies along its centre lines by auto_min_line_unevenness of its width or more, measured as a column’s unevenness is (The measures). It merges into the automatic area it shares the longest edge with, which may be the rest of its own area, the edge measured as a speck’s is (step 4). Every area gives up its thin lines first. A line then goes into what its neighbours keep. On a tie it goes into the area that sews first. A thin line that doesn’t touch an automatic area sews as a line. The thin lines of a shape that turns auto_fill_uneven off sew as lines, as with the logo style, and so do those of a shape that names its stitch. An area whose every part merges sews nothing. SC-I0915 names each line merged, by its area, and where it went (auto::neighbours::lines). The bound of 0.05 is StitchCraft’s own. The dogs’ 80 thin lines vary by 0.09 to 0.46 of their width, and TS-13B’s window lines, drawn with an even pen 0.3 and 0.6 mm wide, by 0.01. The rule goes by the line’s width and how it varies, never by what the picture shows. Each area has the work budget to itself to find its thin lines, and each line to find where it goes. One that needs more keeps its lines, and SC-I0915 says so. The measure of thread astray paints the picture with each line merged in its neighbour’s colour (auto::as_merged), since the neighbour’s thread covers it by the rule.

    Lines merge only while the picture keeps its likeness (REQ-AUTO-095, M13.44, auto::neighbours::lines::parts). A line that doesn’t touch another piece of its colour is a part of the picture by itself, as the likeness measure counts parts, and merged into a neighbour of another colour it takes its colour away, as with a twig or the pale rim of a petal. The lines of one colour that touch each other are one group. A group that touches a piece of its colour that is no speck merges freely, since its colour still shows there. Any other group that is a part costs the picture’s likeness 1 of its colour’s parts, divided by the number of colours. The groups that share an edge with an area merge the cheapest first, those of the colour with the most parts, and of 2 as cheap the smaller, while their cost stays within auto_min_likeness of the picture’s likeness. The rest sew as lines, and SC-I0915 says so. A part is defined once, by auto::is_part, and the measure imports it. At 0, the default, nothing is measured and every line merges. The setting stays off until M13.35’s cap on thickness lands (Merging by likeness).

  4. Specks (REQ-AUTO-008). An automatic area, or a part of one, smaller than 1 mm² is too small to sew: it would sew a knot. It is merged into the automatic area it shares the longest edge with, which may be its own. A speck that fills a hole goes into the area around it, and no hole shows where it was. One that rounding left a hair from the rest of its own area rejoins that. On a tie, it goes into the area drawn first. The edge 2 shapes share is how much of the area’s rings lies within twice the shapes’ tolerance of the speck. A speck that doesn’t share an edge with an automatic area is left out, and so is one whose neighbours need more work to find than the budget allows it: put back as drawn, it could overlap a speck merged in beside it. SC-I0905 names each speck, by its area rounded to a hundredth of a square millimetre and kept under 1 mm², and where it went. A line filled because it is too wide for a column (M13.1) is an area too, so a part of it that small is a speck.

  5. Overlaps (REQ-AUTO-007). Pull draws stitches in from the edges of their shape, so shapes that only meet show fabric between them. Each automatic area reaches its overlap, 1 mm, under each area, satin column, filled line or part’s line or column sewn after it, from where it touches that shape, and no further than that shape as it is sewn. Under an area it reaches that far along its rows and less across them, half as far under a narrow part, and not where an area sewn before it already sews (Less thread where areas overlap). The areas are taken from the last sewn to the first, so each shape is taken as it is sewn: across a line narrower than the overlap, an area reaches on under the area beyond it. Shapes touch where their edges meet within twice the shapes’ tolerance, so a gap that rounding left between edges drawn as one closes too. Along an edge where a shape runs on near the area without touching it, the area doesn’t reach, and fabric shows between them as drawn, but for the overlap round the end of where they touch. A satin column covers the area between its rails as they are sewn, turned to run the same way. Where an area or a part’s line or column sewn after the area covers part of it, as the details on an area digitized whole do, the area is cut away under that shape, the overlap inside the shape’s edge, and that part is sewn once. Sewn whole, it would sew twice there, stiff and thick. A part of the area that such shapes cover whole sews nothing, however near their edge it lies. So does an area they cover whole. A trim or a stop after such an area has no place, as after any element that sews nothing (SC-W0505). SC-I0901 counts only the shapes that sew. A part’s line or column covers its part, and isn’t cut away itself. It sews nothing when the areas, and the lines and columns of other shapes’ parts, sewn after it cover the part whole, and it sews whole when they cover the part in places. A satin column or a line digitized from a stroke and sewn after an area goes over it, and the area is sewn whole under it. Cutting a fill round small letters adds stitches and can leave gaps (Inkscape forum). SC-I0904 counts the areas that reach under others and those cut away. It also names each area cut away whole, which sews nothing. The areas are named in the order they are sewn.

Only automatic areas change. A shape with settings is sewn as they say, and a satin column or a line digitized from a stroke or a part keeps its stitches: a column is sewn past its rails by its pull compensation, 0.4 mm (Settings by width), and by the overlap past a rail that a shape sewn after it runs along (Neighbours that overlap). A fill that bounds no area is left to its fill, which says so. The areas are taken from the last sewn to the first, so that each meets the shapes after it as they are sewn. Each area has the work budget to itself for its specks and for its overlaps, and costs the work of the shapes near it and a unit for each other shape it looks past, not the work of the whole design: what a shape sewn after it paints is found once, with the work budget to itself. An area whose overlaps need more keeps the region it has, and a speck that needs more is left out. SC-I0904 and SC-I0905 say so. A satin column whose area needs more is not reached under, which SC-I0904 says too. The regions are combined by one function, which cuts the rings of both where they meet and keeps the faces by their winding numbers (normalize::region::ops).

An outline round a fill

A tatami fill’s rows end at its edge, and the thread pulls each row’s end in. On a small shape with points, such as a star 5 mm across, the ends of the rows are most of what shows, and the points sew blunt. A digitizer runs a stitch round such a shape after filling it, which draws the edge as one line. auto_fill_outline does that for a design (M13.27, REQ-AUTO-051), read of its lowest automatic shape as the base layer’s settings are.

Each automatic area then sews a running stitch along its edge, in its own thread, in an element of its own straight after the area, named after it with #2. The edge is the area’s as the layers and the specks leave it, before the area reaches under its neighbours: what shows of it. Where a shape sewn after the area touches the edge, the area lies under that shape by the overlap, and a run along the edge would lie under that shape’s stitches and thicken them. So the outline leaves out the edge within auto::TOUCHING of each shape sewn after the area, and of each other element of the area’s own shape, whose columns and lines are the same shape going on. A line digitized from a stroke goes over an area, and hides no edge. The edge is cut into pieces no longer than 0.5 mm, and a piece shows when its middle lies in none of those shapes. The pieces that show in a row are one line, a ring where the whole edge shows. A line shorter than 3 mm is left out, since 2 stitches beside a neighbour’s edge sew a knot.

The setting is on by default since M13.28. M13.27 left it off, for the jumps it cost a traced photo. Shown the badge’s stars with and without it, the owner said that outlines were better all along. The Auto effect’s dialog has a row for it (Settings).

An outline’s stitches follow a round edge. A running stitch keeps to its path within its tolerance, which is 0.2 mm unless a shape sets it. Stitches 2.5 mm long stray 0.16 mm from a circle 9.6 mm across, so the badge’s moon was outlined with 12 sides. An outline has a tolerance of auto::OUTLINE_TOLERANCE, 0.1 mm, unless its shape sets running_stitch_tolerance_mm. Its stitches are then shorter where the edge bends, never shorter than the machine’s shortest stitch, and the moon has 18 sides.

An outline’s stitches lie on its own fill (M13.43, REQ-AUTO-130). A stitch is straight, and a running stitch keeps within its tolerance on both sides of its path. Where the edge bends away from the area, a stitch along it lay up to the tolerance on the neighbour. Across an inward corner that the shortest stitch passed over, it lay further on it. Where the neighbour has another colour, that is a thread of the wrong colour on it. So each line of an outline is moved into the area by the tolerance it keeps to, and its stitches keep within the tolerance of that line: each lies between the edge and twice the tolerance in. Each side moves that far towards the area. At an outward corner the 2 moved sides meet where they cross, so the corner keeps its point. At an inward corner an arc round the corner at that distance joins them, in steps of at most 22.5 degrees. Where a side is so short that its moved line would end before it starts, the side is left out and the sides beside it meet. Rings are opened at the middle of their longest side, where they don’t turn, then moved and closed again. The line folds over itself where such a side starts at an arc or is the first, or where the sides beside it don’t cross, as round a bar narrower than twice the distance. There it goes straight from the end of the moved side before the fold to the start of the one after it, inside the bar. A last side whose moved line would end before it starts ends on the edge. A line shorter than 3 mm is left out, as on the edge. The thread is 0.4 mm wide, so it still covers 0.1 mm past the edge, and the fill’s rows still lie under the neighbour by the overlap.

The engine’s offset curve would find more: it cuts the ring of curves round a line where it crosses itself, and so finds where 2 stretches of an edge come within twice the distance of each other. That work grows with the square of the line’s sides. Offset whole, the traced dogs took 7 to 10 % more work to plan and the pear twice as much, and in windows of 32 sides still 8 to 12 %, past what VectorCraft allows a test sheet. Moving each side costs a few units a side. A neck narrower than the distance is not found, and there the moved line lies past the neck’s far side by less than the distance, as a stitch lay before. An outline whose lines need more than the budget, a unit for each side and for each corner looked at, sews none, and says so with SC-I0904.

An outline is sewn with as few jumps as its lines allow (REQ-AUTO-052). A traced area’s edge is hidden wherever a neighbour sewn later touches it, often for a few millimetres, and each hidden stretch parted 2 lines by a jump. The outline now sews through a hidden stretch of BRIDGE, 25 mm, or less, along the edge and under the shape that covers it, at a stitch for each 2.5 mm. The longest hidden stretch of a ring stays out, because sewing it would join nothing. Under a fill sewn after the area the limit is 12 mm (the outline under a later fill). Of an outline’s lines, the one with an end nearest where the next element starts sews last and ends there. An open line is turned round for that if need be, and a ring starts at its corner nearest that place.

Covering the fabric

The fabric’s colour can’t be chosen. It may be black, so a design has to cover the fabric by itself. The measure of bare fabric (Sewing order, REQ-AUTO-025) passes a patch under 1 mm², and its disc needs 0.45 mm of bare fabric on the grid, so a sliver 0.4 mm wide between 2 shapes passes too. On the traced dog such slivers lay between strands of fur and beside the nose, and on dark fabric each was a dark line. M13.16 of the roadmap made the measure stricter, and built one underlay under the whole design and a wider overlap between neighbours to meet it (REQ-AUTO-027 to REQ-AUTO-029, REQ-RND-003).

The stricter measure

stitchcraft_testkit::fabric::cover paints the picture as the measure of bare fabric does (REQ-AUTO-027).

  • The design is what the picture paints, with the slits between its shapes that are narrower than a thread: the painted places closed with a disc 0.4 mm across. A hole a thread wide or wider stays fabric.
  • Its edge, the outermost 0.2 mm of the design, isn’t measured. A fill’s first row lies up to a row’s spacing inside the outline, and beyond the outline is fabric anyway.
  • Bare is the part of the rest that the top stitches don’t cover, and open the part that the thread of every role leaves uncovered. The base layer is underlay: it shows in a bare place, and it doesn’t make the place covered.
  • A gap is a place where a disc 0.35 mm across fits on bare places, 7 pixels of the grid. A strip of fabric 0.4 mm wide holds 7 or 8 pixels by where it lies, so this disc fits in every such strip, and the 9 pixels of the older measure’s disc fit in none.
  • The base layer lies under a place inside the shape that one of its pieces fills (below).
  • The rim is the band along the design’s outline that the base layer’s offset leaves without a base layer, 0.4 mm wide by default. A part of the design narrower than twice that is all rim.
  • A sliver is a gap no larger than auto_base_sliver_mm2, 0.4 mm², whose every place has the base layer under it or lies in the rim: its part without the base layer lies wholly within that band. Over the base layer its thread shows in place of the fabric. In the rim a sliver lies at the outline and reads as part of it.

A picture passes when no fabric shows inside its design, counting the base layer:

  • Every gap is a sliver. Fabric shows in a larger gap, and in one with a place further inside than the rim that the base layer isn’t under.
  • With a base layer, the top stitches leave no more than auto_base_bare_percent, 0.5 %, of the design bare: the slivers and the places narrower than a thread together.

A design without a base layer has nothing under a gap. It passes with no gap at all and with no more than 0.15 % of its design bare, twice what a picture without gaps leaves. One underlay under the whole design

Ink/Stitch has this as its Knockdown Fill tool. Its documentation says that the tool can make a global underlay and that the offset is then usually negative (fill tools as read on 2026-11-10). What it does, read in lib/extensions/knockdown_fill.py at d59c9ab and told in our words (ADR-0012):

  • Outlines. It takes the area each selected element sews. For a fill that is its shape, grown by its expand, and for a satin column the area between its rails as sewn, its pull compensation included. A running stitch counts as a band 0.3 mm wide along its path, and a ripple as a band of that width along each line of its stitches. A zigzag stroke counts as a band as wide as it sews, and a clone as what its elements make.
  • The outer shape. It unites the outlines and offsets the union by the offset asked for, outwards when positive and inwards when negative. The join style, round or mitre or bevel, shapes the corners that the offset makes, with a mitre limit of 5 unless another is given, and never under 0.1. It then drops points that lie within 0.3 px, 0.08 mm, of the line between their neighbours.
  • Holes. Each piece of that shape becomes one path. With “keep holes”, on by default, the path has the piece’s holes, and otherwise only its outer ring.
  • Place. The paths go before the first selected element in drawing order, so they sew first.
  • Stitches. Each path is a fill whose row spacing follows the stitch length asked for, 3 mm by default: row_spacing_mm is the length times √3/2, written to 4 decimals, with max_stitch_length_mm the length and staggers 2. Its underlay sews at fill_underlay_angle “60 -60” with the same length and spacing, and underpath and underlay_underpath are off. Rows at 0°, 60° and −60° that far apart and staggered over 2 rows put the needle points on a lattice of triangles as long a side as the stitch.
  • It can also frame the selection with a rectangle or a circle that the selection is cut out of, for embossing. StitchCraft doesn’t take that.

Less thread where areas overlap

An overlap is thread under thread. M13.29 measured that the overlaps cause most of the thread where a traced picture sews thick (How thick a design sews), and the owner’s first concern on 2026-11-16 was that thickness. REQ-AUTO-067 (M13.30) takes away the part of an overlap that the pull doesn’t ask for (auto::neighbours::under):

  1. The overlap follows the rows. The thread pulls a row in at its ends and not sideways. So an area reaches its overlap, 1 mm, along its rows, and its pull compensation, 0.4 mm, across them. What it sews under a shape is every point of that shape within an ellipse with those half axes round a point where the 2 touch. Across its rows the overlap is never wider than along them, and without pull compensation it is 0.01 mm wide.
  2. Half as far under a narrow part. Under a part of an area that is narrower than 3 overlaps, the overlap is half: 0.5 mm along the rows, and across them no more than that. A part is narrow where no disc 3 overlaps across fits on the area. The areas on both sides of a part just under 3 mm wide then leave a third of it free, where 2 whole overlaps filled a part 2 mm wide between them. This is the owner’s idea of 2026-11-16, and digitizers work so by hand: one guide extends the lower colour 1.5 mm under bold areas, 1 mm under fine details and 0.3 to 0.5 mm under delicate lettering (Stitch Era’s magic wand, a retailer’s article).
  3. One overlap under a shape. Where 2 areas would both sew under a shape sewn after them, only the area sewn first sews there. This is the owner’s idea too: one overlap then lies under the shape at that place, where 2 lay at the corner of 3 shapes. The areas are taken from the first sewn to the last. A piece of an overlap that this cuts off from what shows of its area is left out.

Under a satin column, and under the part that a running stitch or a column sews along the middle of, an area reaches its whole overlap whichever way its rows run, as before. A column’s stitches don’t cover its ends and its bends as a fill’s rows cover an area, and a running stitch covers a thread’s width of its part. Where what an area sews across a line’s part meets a shape beyond the line, the area reaches on under that shape from there. The 2 measures

A plan is measured where the machine sews it, each needle point on the machine’s grid of 0.1 mm. The engine’s own positions have digits that no file shows. Measured on those, the warning of VectorCraft’s export differed from the one stitch export gives for the same file (the compatibility gate on 2026-11-16). The grid is laid from the plan’s first needle point (M13.35). The same stitches measure the same wherever they lie. On the machine’s own grid, a test sheet drawn on a page measured otherwise than its machine file, and the last pass (The last pass) changed the two otherwise. A coordinate is rounded to a millionth of a millimetre first. Shapes drawn on round numbers put needle points half way between 2 points of the grid, and without that such a point goes to one or the other by the last digits of its position.

Both are sums over a window of 1 mm², on square cells 0.5 mm wide. Each cell is 10 pixels of the grid that the bare fabric is measured on, so the 2 pictures can be laid on each other. The measures have a value at each spot, a corner of the cells, whose window is the 4 cells that meet there. Spots so lie half a window apart. The cells are this coarse because planning measures every design. On cells of 0.2 mm the measure took 80 % as long as planning a test sheet, and VectorCraft stopped the export of TS-13A for the instructions it ran. On these cells it takes 2 to 3 %.

Thread, in fills. Every stitch is a ribbon of thread 0.4 mm wide, whatever its role, since the needle goes through underlay and travel stitches as it goes through top stitches. A window’s thread is the length of the ribbons in it, times 0.25 mm, over its area. A fill with rows 0.25 mm apart, which is StitchCraft’s fill by default, so measures 1, and the number reads as “this many fills deep”. A satin column measures 1.25, because it lays 2 stitches every 0.4 mm. The base layer measures 0.3.

The sources count objects on each other, and a fill is the object here. Counted in layers of thread, one of our fills is 1.6 layers, because its rows lie closer than a thread is wide. The fill that the sources call standard has rows 0.38 to 0.4 mm apart, so ours is the denser one. To read a number of this page in layers of thread, multiply it by 1.6.

Needle points per mm². Each stitch’s needle point counts once. A lock’s are left out, since every design ties its locks on purpose. This measure finds what the first one misses: short stitches and turns bunched in a small patch, which cut the fabric and break thread on their own.

A square 15 mm a side that the engine fills 1, 2, 3 and 6 times measures as many fills 2 mm inside its edge: 1.03 times the layers on average, since the needle also travels under its rows, and 0.89 to 0.97 times at the least.

The last pass

The rules of single shapes can’t bring the dogs to the cap: 5 to 8 elements meet at their thickest spots, each with a little thread, and no rule of one shape knows the sum: the finished plan does. So a plan of a design digitized automatically is measured once, and where a spot sews above 4 fills a last pass takes thread (REQ-AUTO-074, auto/thin.rs). Taking a needle point out of a run takes no thread away, since its 2 stitches become one as long, and cutting a run leaves a jump thread. Thread leaves a spot only where the stitching doubles back on itself, or where the end of a row can move. The pass looks at the stitches within 2 mm of a spot above the cap and takes, in this order:

  1. travel that goes out and comes back within 0.1 mm of where it was 2 needle points before: those 2 points go, and the stitch before them runs on to the one after;
  2. a lock’s stitches beyond one back and forth, where it has 4 or more;
  3. the base layer’s row ends, where a row turns to the next within 1 mm and the 2 rows run nearly opposite ways: the end and the next row’s start move back along their rows by the overlap (auto_overlap_mm), or by half of it;
  4. the other shapes’ top row ends, moved the same way.

A row’s end moves only where it is hidden at both places: the top stitches of the elements sewn after it lay 1 fill or more at its old and new points. The pass measures them from the plan’s end, so that thread taken from a later shape no longer hides an earlier one. The pass skips a change that would leave a spot it lays thread in thicker than both the cap and what it was. It skips one that would make a stitch shorter than the machine’s shortest (a lock’s 0.2 mm into or out of a lock point) or than the turn it replaces, or longer than the machine’s longest. It keeps every top stitch that shows, and it doesn’t make a jump thread. It keeps the measure up to date stitch by stitch (Thickness::add and remove) and hands it to SC-W0913, so that the design is measured once. SC-I1119 says what it took.

Likeness

Each merge of automatic digitizing takes a jump thread or a thread change away: a speck (REQ-AUTO-008) and a thin line (REQ-AUTO-090) sew as part of their neighbour. A merge can also take what makes a picture read, such as an eye or a stripe. The rules go by geometry and can’t tell an eye from noise. The likeness measure checks afterwards what the geometry kept (REQ-AUTO-093, stitchcraft_testkit::fabric::likeness).

The measure

The trace is the design as drawn, before anything merges, painted as the bare fabric paints it at 0.05 mm on a grid round the design alone. The stitches are painted on the same grid: each pixel has the colour of the last top stitch whose thread, 0.4 mm wide, covers its centre. Underlay and travel stitches lie under the top stitches, as locks do, and are left out.

  1. A colour’s parts are its pixels that touch at a side or a corner.
  2. A part counts when it is as large as the smallest area sewn by default, 1 mm², and a disc a thread across fits in it. Smaller, it is a speck, which the rules merge or leave out, and no stitch of its own sews it narrower.
  3. A part’s core is its pixels that a disc a thread across, centred on them, fits in.
  4. A pixel is shown when the stitches have its colour within half a thread of it.
  5. A part is kept when half of its core or more is shown.
  6. A colour’s likeness is the share of its parts kept, and the picture’s is the mean of its colours’.

A share of matching pixels is ruled by the large patches. An eye of 1.44 mm² on a field 20 mm wide is 0.36 % of the picture, and its loss moves that share by less than the stitches’ edges move it. Each part counts once, whatever its size, and so the eye’s loss halves the likeness of that picture of 2 colours. Each colour counts once too, so the few dark parts of a face weigh as much as a colour’s many pieces of shading. A change that keeps every part keeps the likeness, however it moves the stitches.

The core leaves out a strip half a thread wide along a part’s edge, where its neighbours’ rows end. A strand 1.4 mm wide that a running stitch sews along its middle shows its colour on 0.8 mm of its core’s 1 mm, and is kept. The parts of the traced dogs are shown on less than a fifth or more than three fifths of their cores, so the line at a half moves no count.

A traced photo has hundreds of bits of texture smaller than 1 mm². Counted, they ruled the measure as the large patches rule a share of pixels: 476 of a traced magnolia’s 972 parts that a thread fits in are such bits. Parts that digitizing merges as specks show when the smallest area is raised.

Sewing order

Automatic elements sew in an order StitchCraft chooses (stitchcraft_engine::auto::neighbours::order, M13.3). The order is chosen after specks are merged, so that a speck merged into an area is no element of its own, and before areas reach under their neighbours, which follows it. VectorCraft’s Auto Grouping draws each shape together with the shapes inside it. Sewn in paint order, a picture traced with it changes thread at nearly every shape, and each change is a stop to rethread a home machine. The order comes from 6 rules.

  1. What overlaps keeps its paint order (REQ-AUTO-010). Of 2 shapes whose paint overlaps, the lower sews first, or it would cover the upper one. Paint order is the design’s, with each area digitized whole moved back before its details (Neighbours). An area paints the region it sews once the layers are flattened, and a satin column the area between its rails as they are sewn. Lines paint the areas their strokes paint as drawn, and a part’s line or column the part. Shapes that only meet, as abutting paths do, may sew in either order. Rounding leaves a sliver no wider than twice the shapes’ tolerance between edges drawn as one, and shapes overlap only where their overlap is wider. Where 2 lines 0.1 mm wide cross, they overlap.
  2. A line after the fill it borders. A line that touches a fill without overlapping it sews after the fill and covers its edge. Its running stitch is as wide as its thread. It can’t reach under the fill, and a fill sewn after it lays the ends of its rows on it. Rule 1 comes first. A line that rule 1 already sews before the fill, through the shapes it overlaps, keeps its place.
  3. The fewest thread changes (REQ-AUTO-037, M13.22). Within rules 1 and 2 the elements sew in batches of one thread. Once a thread is sewing, every element of it that is free to sew does, and those they free: an element is free when every element that must sew before it has. Sewing more of a thread now never costs a change later, so an order is a row of batches, and the row that changes thread least is searched for. The base layer sews before the first automatic element, so its thread is sewing when that element’s run starts. Threads are the same when their colours are, as plan assembly counts thread changes. A PES file gives different colours different palette entries while they last (REQ-THREAD-002), so 2 colours are one thread to the machine only past the palette’s 64 entries. An element sewn in several threads (M10.5), as a tartan fill is and a gradient fill will be, moves as one. Its colours stay together, in the order its generator sews them. It is a batch of its own, which costs a change unless the thread it starts in is sewing. The batch of the thread it ends in follows it (REQ-AUTO-024). Its threads are read before it is generated, from its shape and settings.
  4. A satin column after the fill it borders, where that costs no thread change. A satin column that automatic digitizing made covers the fill’s edge when it sews after the fill. Sewn first, it reaches its overlap under the fill (Neighbours), so the fabric is covered either way. Of the rows with the fewest changes, the search takes the one in which fewer columns sew before a fill they border. The column then waits for a later batch of its thread when the row has one after the fill. Satin columns with settings go by rule 2.
  5. Details last, where that costs no thread change (REQ-AUTO-096 to REQ-AUTO-098, M13.40), when the design turns auto_details_last on. An eye, a nose or a mark on a patch sews after the shapes round it, so that no fill’s rows lie over it (Details last). Of the rows with the fewest changes, the search takes the one in which fewer details sew before a shape round them, as it does for rule 4, and a detail waits for a later batch of its thread when the row has one. A line or a column round a detail goes by rules 2 and 4.
  6. The nearest next. Of the free elements of a batch, the next is the one whose box lies nearest the box of the element sewn last. On a tie it is the one whose box’s centre lies nearest, and then the one drawn first. Each element then starts and ends at its points nearest its neighbours (REQ-GEN-003).

The search (stitchcraft_engine::auto::neighbours::order::fewest). Finding the fewest thread changes under rules of what sews before what is hard in general, and a design has few threads. The search keeps rows of batches as far as they go, each with the elements it has sewn and the thread it leaves sewing. It goes on from the row with the fewest changes so far and still needed, one for each thread that has elements left. Its first whole row then has the fewest changes of any order. Of 2 rows that sew the same elements and leave the same thread sewing, it keeps the one with fewer changes, then the one with fewer columns before their fills, then the one found first. It tries the threads of the free elements in paint order. A design then sews the same on every run. Each run of elements that nothing moves across is searched on its own, and starts in the thread the run before it left. Where elements with settings of a run sew before its first automatic element, the base layer sews between them and it, which the search doesn’t count. order/fewest/tests.rs compares the search with every order of 300 small runs drawn at random.

tests/auto_order.rs checks rules 1 to 4 together on random designs of squares and lines, wherever the shapes fall.

Elements with settings keep their order among themselves, and automatic elements move round them within the rules. The parts of a shape sewn as several elements, such as a line’s satin columns, keep their order too, so that a trim after the shape still comes after its last part. --sort-colours lets the elements with settings move as well (REQ-AUTO-011), whether or not --auto is given. It is for a design drawn in an order that suits drawing it rather than sewing it. The switch is the command line’s. VectorCraft’s exporters order the automatic elements when their auto option is on, and sew the elements with settings as drawn. An element with a stop after it keeps its place: the elements drawn before it sew before it, and those drawn after it after it. A user sets a stop for a reason, such as placing appliqué fabric, and it comes where it was drawn. SC-I0907 says when the order isn’t paint order, with the thread changes of each, those inside the elements sewn in several threads among them. M10’s routing tools don’t start from this order. They route satin columns and running stitches drawn by hand as Ink/Stitch’s tools route them, and write the route into the document (routing tools). Each element that automatic digitizing makes sews its underlay just before its own top stitches. The rules leave underlays_first off (ADR-0018).

Shapes are near when their boxes come within twice the shapes’ tolerance of each other. An automatic area’s box is round its region, and a narrow part’s line’s round the part. Any other shape’s box is round its path’s points, grown for a stroke by half its width times √(L² + 1) for a miter limit L. That holds the corners of a miter clipped at its limit, as a satin column’s rails clip it. Other strokes grow by half their width times √2, which holds a square cap’s corners. Rule 4 measures with the same boxes. The order finds a shape’s paint only when the shape is near an element that moves.

Work (REQ-AUTO-012). Each element has the work budget to itself to find how it lies beside the shapes drawn after it. It costs a unit for each of them, and the work of those near it. One that needs more keeps its place in paint order as an element with a stop after it does: nothing moves across it. An element after it that one before it frees still waits its turn after it, and each element sews once. A shape whose paint can’t be found within the budget keeps its place beside the shapes near it. Finding the rows of batches has the budget once for the whole design. It costs a unit for each element looked at and 1,000 for each row kept. The default budget keeps 500,000 rows at most. From the run that needs more on, the elements sew as they did before M13.22. Each thread sews while an element of it is free, then the thread of the first free element in paint order, and every satin column sews after the fills it borders. Placing the elements has the budget once more, and costs a unit for each free element looked at each time an element is placed. An order that needs more sews the elements not placed by then in paint order, after the others. SC-I0907 says each. SC-I0904 says it of a satin column instead, whose area the areas sewn before it then don’t reach under either. A fill’s generator needs the work of its region too, and says it of a fill (SC-E0004).

Details last

(REQ-AUTO-096 to REQ-AUTO-098, M13.40.) A digitizer sews an eye, a nose or a mark on a patch after the fills round it, so that no fill’s rows lie over it. StitchCraft can’t tell an eye from a speck of noise, and no rule may know what a picture shows. A detail is known by geometry and order alone. It is an automatic area that meets a larger automatic area without overlapping it, and that the shapes round it close in on. The strip one tolerance wide round its region lies under what the other shapes paint, grown by twice the shapes’ tolerance, for 3 quarters of its area or more (order::Order::closed_in). An eye or a mark has neighbours all round it. A patch at the picture’s edge is open along it, and a patch of fur is larger than the shapes inside it.

What the layers’ rule missed. Neighbours already digitizes an area wider than a satin column whole under the details in its holes, and moves it back before them. That rule missed 4 cases, each shown on main before M13.37 by a case of tests/auto_details.rs:

  1. A detail where 2 or more patches meet lies in the hole of none of them, and the rule left it where it was drawn. The cases draw a mark 12 mm square where 2 patches meet.
  2. An area no wider than a satin column keeps its holes. Where it sews as a fill, as a ring 3 mm wide round a square did, the square in its hole sewed first. Since M13.37 such a ring sews as satin columns, which sew after the square as an outline does, and the square reaches under them: no miss. A ring that asks to sew as a fill sews before the square with the setting off too, and the case stays to keep it so.
  3. An area that can’t move back past a shape with settings near it opens its hole again, and the detail sewed first (REQ-AUTO-097). A stop keeps every element on its side of it, so a detail drawn before a stop still sews before an area drawn after it.
  4. A fill sewn after a detail eats its edge. On the marked patch, sewn on main, the black dot measures 5.5 mm where it is drawn 6 mm, and the diamond 11.7 mm where it is drawn 12 mm: the later fill’s rows and their pull compensation reach over them.

Wishes to the search. Each detail sews after the larger areas it meets where that costs no thread change, as a satin column does after its fill (rule 5 above). Of the rows of batches with the fewest changes, the search takes the one that sews fewer details early. A detail then waits for a later batch of its thread. The owner’s machine has one needle, and each thread change is a rethread by hand. As hard rules, details last took the traced photos in 6 threads from 8 thread changes to 13 and 14. In 9 threads the search ran out of its budget, and they changed thread 35 and 38 times.

Off by default (REQ-AUTO-098, M13.48). The rule runs only when the design’s lowest automatic shape has auto_details_last on. Off, the order skips the search for details, and a design sews as it did before M13.40. The rule landed off, and waited for one cap on thickness at the end of planning (M13.35). Reordering fills can raise the thread at a spot where no detail lies. A fill that moves for a detail starts and ends elsewhere, and its own travel runs elsewhere under its rows. It also reaches under other neighbours. On one traced photo the thread over one spot rose from 4.69 fills to 5.49 by one wish: the fill that moved crossed the spot 3 times more with its own travel, 9.50 mm of its thread in a box 1 mm across where it had 3.76 mm, with the same stitches. On another the wishes changed which of the rows with equally few changes the search took, and a fill sewn later retraced a row. Nothing in the shapes’ geometry told the wishes that do this from those that help. Leaving out the wishes of details whose rim the larger area covers less than a share, for every share tried from a quarter to all of it, kept one photo at its old thickest spot and raised another. A check that plans twice and keeps the better plan, or a cut-off by the number of areas, would only hide that. An area count can’t even tell a photo from a logo: a traced photo can have fewer areas than a badge. Once the cap limits every spot, a reorder can’t pile thread anywhere, and so M13.45 turned the setting on by default. M13.48 turned it off again, for its jump threads (off by default again, below).

A detail inside a detail (REQ-AUTO-108, M13.45). A detail can have details of its own, as a pupil on an iris or a window in a door does. With both settings on, a traced dog’s grey area that the darker fur closes in on moved to sew after the fur, while the tan patch on it, which would cost a thread change to move, stayed where it was. The grey’s outline and rows then lay over the tan’s edge. So a detail moves only together with what sews on top of it. A wish moves its second element later. Its nest is that wish, each wish that something sews after that element, a detail of it or a satin column bordering it, and the nests of those. The search grants a nest whole or not at all. It also keeps the row itself from doing the same. Of the rows with the fewest changes it takes the one that misses the fewest inner wishes, those whose first element another wish moves, and only then the one that misses the fewest wishes. So wherever a row with as few changes keeps a pupil on top, the search doesn’t take one that sews the iris after the fur and leaves its pupil under it. A nest goes by the shapes’ sizes and where they meet. It doesn’t need a second plan or a measure of what shows. Runs in place of jumps

Between 2 shapes of one thread the needle jumps, and a machine with one needle cuts no thread at a jump: each is a thread to cut by hand. Where the stitches sewn later cover a way from one shape to the next, plan assembly sews a run along it instead (REQ-AUTO-053, M13.17, stitchcraft_engine::moves). The needle neither ties off nor jumps. The run is a row of travel stitches of the element it leads to, 2.5 mm long at most, and the shapes sewn after it hide it. Assembly decides it, because only there is it known where the needle is and whether a move is sewn on or jumped (REQ-ASM-002). Only moves between elements that automatic digitizing made are looked at. Elements with settings keep their jumps, as Ink/Stitch sews them.

What covers is read from the stitches as generated, and not from the shapes: a fill with rows far apart covers nothing, whatever its outline says. Every stitch of the top layers is painted 0.4 mm wide on 2 grids of 0.2 mm. One records, for each cell, the last fill or satin column whose thread covers it. The other records the last stitches of any kind, whose colour is what shows there. Underlays and the base layer are not painted. A cell is hidden from a move when a fill or satin column sewn after the move covers it and every cell within 0.4 mm of it. The run then lies as far inside what covers it as an underlay lies inside its fill, clear of the ends of the rows, where a fill covers least. A cell is also hidden where the stitches that show are of the run’s own colour and sewn after the move. The outline that follows a fill is such: the run lies under it as the first pass of a double line.

The ends. An element ends on its own stitches and starts at its own edge, so a run can’t be hidden from its first millimetre to its last. Within 0.8 mm of each end, less than the 1 mm at which a stretch of thread counts as showing (REQ-AUTO-026), it may cross cells of its own colour sewn before, and cells covered later without the 0.4 mm to spare.

The way is the shortest over the cells a run may cross, found by a search that goes on from the way that is cheapest so far with what is still ahead. It steps to the 8 cells round a cell and counts in whole tenths of a cell. Equal ways are taken in a fixed order, which gives a design the same runs on every machine. A run goes round what would show it, up to twice the move and 10 mm in length. The search stays within 10 mm of the box of the move’s ends. The way is then pulled straight wherever the straight line keeps to those cells, and each straight piece is sewn in equal stitches, with a needle point at every corner, so that no stitch leaves the way.

A move that is sewn on, within the collapse length, stays a stitch unless it would show for 1 mm or more on another colour or on bare fabric. Then it becomes a run where a way is hidden. Where none is, it stays a stitch. The roadmap’s row had it become a jump there. Measured, that left each traced dog 5 to 15 jump threads more, each no longer than the stitch it replaced and harder to cut than the stitch is to live with, so the stitch stays and tests/auto_photos.rs goes on counting it.

Work. Painting and the searches share the work budget once for the whole design. Each cell of the grids costs 100 units. The default budget then allows a design of 450 mm by 450 mm, and a larger design gets the same memory at most. A stitch costs a unit for each cell of its box, and a search costs a unit for each cell of its box and for each cell it looks at. When the work runs out, the moves from there on are sewn on or jumped as they were, and SC-I0914 names the element where it ran out.

Previews in VectorCraft

The Auto effect is a live effect like the plug-ins of each stitch family (plug-ins). VectorCraft runs a group’s effects on each path inside it (REQ-VC-006), so the effect on a traced group previews every path’s stitches, each sewn as its width says. A live effect is given its path and its paints alone. Like stitch export, it reads the path as an area when a fill paints it, and as a line along its topmost stroke. Its preview shows each shape’s stitches without the overlaps, the merged specks or the order, which stitch export adds. VectorCraft draws what a live effect returns with every paint of its object. The stitches come back as gaps in the area that the fill fills when a fill paints the object, and as lines that its stroke draws otherwise.

Digitizing is most of a preview’s work, from about 1,450 instructions a unit to 2,260 in VectorCraft 0.18.0’s host, and a live effect has 50 million (live-effect previews). A square’s takes 12,900 units, an L’s 21,000 and a ring’s 31,800. The auto level digitizes within eight tenths of the budget, then shows each element made as auto shows its family’s: a fill’s top rows, and a satin column’s and a running stitch’s every stitch. When that costs too much it shows the outline, as a larger square, an L, a ring and most traced letters do. Exact shows every stitch, and outline the path, hatched across a fill. A preview that costs more than the level allows shows less, with SC-I0810, as the other effects’ previews do. The command line’s preview always shows every stitch.

Tracing again replaces the group with a new one, without the effect. Apply the effect after the last trace, or use --auto, which works without it.

  • Effects in filter objects (0.15, P8). A filter could set on each path the effect of the family its width chose. The user then adjusts it in that effect’s dialog.

Text in pictures

Text traced from a picture is shapes, and the rules for shapes sew its letters: strokes as satin columns, small parts as running stitches. Small letters come out ragged, and neighbours that the tracing joined sew as one blob. An embroidery font is drawn for the needle, and lettering sets text in one (fonts). The pass is stitchcraft_svg::lettering::pictures. It works on a design once a reader has made it and before anything is digitized (REQ-AUTO-063 to REQ-AUTO-066). What is left of the traced shapes is then digitized as if the letters had never been traced, with its overlaps and its base layer.

Both readers already give a shape’s name to its element, so one pass serves both. The marker needs a fill or a stroke, since a reader is given only objects that paint. It is never sewn.

Which shapes are the letters

Every subpath that lies wholly inside the marker is taken out, of every element. A subpath is one closed outline. Image Trace keeps all the areas of one colour in one compound path, so a letter is a subpath of its colour’s path, not an object, and the hole it leaves in the colour round it is a subpath of that colour’s path. Taking both out removes the letter and closes the hole. An island of the background’s colour inside a letter, its counter, goes the same way. What is left of the background is its own outline, so it sews whole under the lettering. A picture drawn in layers has no holes to close, and its letters are taken out as whole objects.

So the background is told from the letters by reaching outside the marker, and by nothing else. Colours are not compared, since a traced edge has specks of other colours along it.

A subpath that crosses the marker’s edge stays as it was traced. When more than half of its points lie inside, it is probably a letter partly outside the marker, or a letter the tracing joined to something outside, and SC-W1114 counts those. Points are those of the outline flattened within 0.05 mm, which is a tenth of the narrowest stroke an embroidery font sews.

Size and place

What was taken out is measured along and across the line the text follows. A closed marker’s line is level, so along is across the page and across is up. The text is set once at the font’s own size and measured the same way. Then:

  • Height. The scale, to a tenth of a percent, makes the box of what the text sews as tall as the box of what was taken out. The box holds parts that reach below the baseline, so a p in the text is measured with its tail.
  • Baseline. The text’s box is centred on the traced letters’ box across the line. The baseline lies as far above the box’s bottom as the text’s lowest point lies below the baseline.
  • Width. Every gap between 2 glyphs, a gap between words too, is widened or narrowed by one amount until the text is as wide as the traced letters. The amount is at most half the letters’ height wider and a tenth of it narrower. Past half a height a word reads as separate letters. Closer than a tenth, the strokes of neighbours sew over each other. The text is then centred on the traced letters along the line.
  • Along an arc. The baseline is the marker’s line moved sideways to the baseline’s distance, each corner of it pushed out along the line that halves the corner. Lettering along a path then places each glyph on it and turns it whole (along a path).

The scale stays within the heights the font sews at. Letters shorter or taller than that are set at the nearest height the font sews, centred on the traced letters, and 2 warnings say so: lettering’s own SC-W1106, with the font’s range, and SC-W1115, with both heights and both widths in millimetres. SC-W1115 is also said when the text ends up more than a tenth of the letters’ height from their width. The traced letters are not kept in such a case. Text at a height the font sews well reads better than a blob, and the picture shows the difference.

A font that sews in one thread takes the thread that painted the most of what was taken out. A hole counts against its thread, so the background, whose holes are as large as the letters, never wins. A font of several colours keeps its own. The lettering’s elements sew after the last element a subpath was taken from, which puts them on the background. SC-I1112 names each marker with the count of outlines taken out, both heights, the text and the font.

Nothing is taken out before the lettering is set. The font chosen by the letters’ weight

The owner asked on 2026-11-16 why lettering that replaces big letters looks lighter than the picture. The stitches were right. The one font built in was a light one. M14.8 measures how bold letters are and builds in a bold font to choose by that measure (REQ-AUTO-080, REQ-AUTO-081).

The measure is the width of a stroke over the height of a letter, found the same way on a traced outline and on a font’s satin columns (pictures::weight). Each closed outline is taken at 48 places evenly spaced along it. From each a ray goes straight into the shape, as far as the next edge. The side that is in is the one where the ray meets the outlines an odd number of times. The stroke’s width is the median of those distances. The long sides of a stroke outweigh its ends and its joints, whose rays run along the stroke and find its length. So an I and an O of one pen measure alike, which the area over the outline’s length doesn’t give.

  • Traced letters are the subpaths taken out of the thread that painted the most of them. The holes the letters leave in the colour round them belong to another thread and aren’t measured. A letter drawn as a line is as wide as the line. The height is the one the lettering is fitted to.
  • A font is measured on its capital letters A to Z. Each satin column’s 2 rails are closed into an outline. The height is the median height of what each letter draws. Both are as drawn: a column’s pull compensation and the thread’s own width add to what sews, for traced letters as for a font’s.

Marks that keep parts

Automatic digitizing decides by geometry and measures alone which small shapes are specks to merge (step 4 of Neighbours) and which thin lines merge into their neighbours (step 3, and merging by likeness). Details last decides by geometry too which parts sew last. Geometry can’t know which small part a person cares about. The same speck is noise in one picture and the point of another, such as a bird’s eye or the dot over a letter, and in other pictures a flower’s centre or a window. M13.39 lets the person say so with a mark, which works on any subject and names none.

The rule

A mark is an area of the design. Automatic digitizing sews the parts that lie wholly inside it by their width, where it would merge them, and changes nothing else (REQ-AUTO-104 to REQ-AUTO-107).

  • Which parts. The parts of the automatic areas as the layers leave them once flattened (step 2), each one connected piece of one area with its holes. The speck and line steps look at these pieces. A part is inside a mark when every point of its outline is, flattened within 0.05 mm as a text marker’s subpaths are.
  • Specks. Automatic digitizing doesn’t merge a marked speck into the area beside it, or leave it out. It sews by its width, as a larger part does. Narrower than the narrowest satin stroke everywhere, it is a running stitch along its middle, and wider, satin columns or a fill. A speck of 0.8 mm², 1.6 mm by 0.5 mm, sews a running stitch 1.6 mm long.
  • Thin lines. A marked thin line sews as a line in its own thread, whatever the likeness bound (auto_min_likeness).
  • Colour. Merged, a part sews in its neighbour’s thread, and marked, in its own. The threads of a picture are the trace’s, and a mark doesn’t change them.
  • Partly inside. Automatic digitizing decides a part that crosses the mark’s edge as if there were no mark, since a part cut at the mark’s edge would sew an edge the picture doesn’t have. A person who wants it drawn draws the mark larger.
  • Left alone. The rules of the background, the flattened layers, the widths, the order, the overlaps, the base layer and the cap on thickness go as without a mark. The order they find can differ, since every part sewn is a shape more (what marks sew). A marked part reaches under its neighbours, and they reach under it, as for any part. A speck or a line outside the mark may still merge into it. Details last stays its own setting: a marked detail sews last when auto_details_last is on, as it would unmarked. The mark doesn’t name a stitch. For another stitch, a person gives the part its own effect, as for any shape.

One mark covers what the row of M13.39 asked: a marked part’s lines and specks don’t merge, and it sews by the rule of its width. A second mark, to merge what the rules sew, isn’t proposed, since the pictures measured didn’t need one.

Drawing a mark

A mark is a shape named stitch:keep, or stitch:keep and a note of the person’s own, such as stitch:keep left eye. The name is read as every marker’s: in any case, after any white space. Its area is read as a text marker’s is, by the same code. A closed shape’s area is what its outline encloses. For an open line with a stroke, it is the band within half the stroke’s width of the line, between its ends. A line suits a whisker or a twig. The mark needs a fill or a stroke, since a reader is given only objects that paint, and a rectangle or an ellipse drawn with a stroke and no fill shows the picture under it. It is never sewn.

  • In VectorCraft, the person draws the mark with VectorCraft’s own tools over the traced picture and names it in the Layers panel. VectorCraft 0.23.0 gives a plug-in no canvas tool. A group or a layer so named is not a mark, and SC-W0807 says so (REQ-VC-031).
  • In an SVG file, the mark is an element whose inkscape:label is the name.
  • From the command line, --keep LEFT,TOP,WIDTH,HEIGHT marks a rectangle in percent of the box round the design’s shapes, as --text does, read by the same code (REQ-CLI-021). The marks are named keep-1, keep-2 and so on, and a bug-report bundle keeps them with the rules’ settings.

Read when the design is planned. The roadmap’s row planned an Apply Marks command. Instead a reader takes the marks out of the design’s elements and gives them to the design, as it reads text markers, so stitch, File › Export and the bug report each read them on every plan. A command would copy what the names already say, and its result would go stale when the picture is traced again. The Auto effect’s preview shows each shape alone and doesn’t merge, so it looks the same with a mark or without one (previews).

Where it runs

The readers take each mark out of the design’s elements and give it to the design, with its id (stitchcraft_engine::design::mark::Mark, mark::taken_out). An object painted with a fill and a stroke is read as 2 elements of one path, and is one mark. The reading of a marker’s area lies in the engine (design::mark::Area), and the text markers of stitchcraft_svg::lettering::pictures use it from there. Planning reads each mark’s area once (auto::marks), with the budget’s work to itself. Automatic digitizing tests a part against the marks where a step would take the part away: in the width rules, which leave a speck in its area’s fill (auto::narrow), and in the steps of thin lines (auto::neighbours::lines) and of specks (auto::neighbours::specks). The step of thin lines tests every part of every automatic area, so that each mark knows what it holds. Testing a part costs a unit for each mark, and where the box round the part lies in the box round the mark, a unit for each of the part’s points and each segment of the mark, charged to the budget that step has for the part. A part that needs more is decided as if there were no mark, and SC-I0916 says so. Without marks, nothing is tested and nothing is charged.

SC-I0916 names each mark with the parts that lie wholly inside it, and how many of them sew that would have merged, as specks and as thin lines. SC-W0917 names a mark that encloses no area, a mark with no part wholly inside it and a mark in a design without an automatic shape, which then sews as without it.

A guide on one shape

Automatic digitizing chooses the rows of each fill by geometry: every fill has the rows of auto_fill_angle. No rule can know the form that the rows of fur or a ribbon follow. The person draws it. Before M13.24 a guided fill needed the shape taken out of automatic digitizing by hand, which lost its overlaps with its neighbours, the base layer under it and its place in the sewing order. A guide keeps all of them, and works on any subject without naming one.

The rule

A guide is a line the person draws over the picture. Each filled part of an automatic area that the line crosses sews as a guided fill whose rows follow it. The other parts and the steps after them sew as without the guide (REQ-AUTO-109 to REQ-AUTO-111).

  • Which parts. The parts the rules by width leave filled (stitch types by width): the broad parts of an area, its compact and uneven parts, and the broad pieces of a part split by width. A part follows a guide when a stretch of the guide’s line lies inside it where the area shows. An area digitized whole under the details that fill its holes (neighbours, REQ-AUTO-023) shows only round them, so a guide drawn over a detail steers the detail and leaves the area under it alone. Specks, under the smallest area auto_min_area_mm2, stay in the area’s fill and merge as before.
  • The parts it crosses. Unlike a mark, which keeps the parts lying wholly inside it, the guide steers the parts it crosses. The guided fill lengthens the guide straight on at both ends until its rows cover the whole part (guided fill). A guide that crosses only a corner of a large part steers all of it. The person sees that in the exported file’s preview and draws the guide again.
  • Parts sewn along their middles keep their stitches. A satin column already lays its stitches across its width, which follows the part’s form, and a running stitch follows its centre line. Such a part sews the same stitches when a guide crosses it, and SC-I0918 counts it.
  • 2 guides on one part. The part follows the guide drawn last, the one a person sees on top. Blending 2 guides would guess what the person meant.
  • One element for each area and guide. The parts of one area that follow one guide are one element, since a guided fill sews several parts nearest the needle first. These elements come after the area’s other elements, its fill and its parts sewn along their middles, in the order the guides are drawn, so that the other elements keep their names. The first element of an area keeps its name and the others are numbered, so a guided fill is the area’s own element when nothing else of the area sews. The area keeps its thread.
  • Left alone. The background, the flattened layers, the specks and the thin lines go as without a guide, and so do the rules by width, the overlaps, the base layer and the cap on thickness. The guided fill takes its own defaults and the area’s other settings. The base layer keeps its rows across auto_fill_angle, so under a guided fill it lies at an angle that changes along the rows. Each element a guide makes is a shape more to order, so the order can change (what guides sew).

The guide’s line

The guide’s line is its first subpath, as a guided fill reads its guide with the copy strategy, its default. Its stroke’s width is ignored. A closed guide is opened where it closes, as a guided fill opens it. Other subpaths are ignored.

Drawing a guide

A guide is a shape named stitch:guide, or stitch:guide and a note of the person’s own, such as stitch:guide left petal. The name is read as a mark’s, by the same code (design::mark::note), and the readers take guides out of the elements beside the marks (mark::taken_out). It is never sewn.

  • In VectorCraft, the person draws the guide with the Pen or Pencil tool over the traced picture and names it in the Layers panel. VectorCraft 0.23.0 gives a plug-in no canvas tool. stitch:guide is the name VectorCraft documents already give a guide grouped with the shapes it steers (the markers table). A path so named keeps that meaning for shapes with settings, and is also a guide of the design for every automatic area it crosses, wherever it lies in the layers. A traced picture lies in one layer, and a person draws all its guides in that layer. A guide its group doesn’t use is no longer said to be unused (SC-W0807) when the design has an automatic shape, and an automatic shape grouped with a guide alone is no longer told that its markers are unused. SC-W0919 names a guide that steers nothing (REQ-VC-032).
  • In an SVG file, the guide is a path whose inkscape:label is the name. Ink/Stitch’s guide line, a path with its marker grouped with a shape, keeps its Ink/Stitch meaning and guides only that group.
  • From the command line, --guide X,Y,X,Y… draws a guide through 2 points or more, in percent of the box round the design’s shapes as --keep reads its numbers, joined by straight lines. A few points serve, since the guided fill smooths its rows. The guides are named guide-1, guide-2 and so on, and a bug-report bundle keeps them with the rules’ settings (REQ-CLI-022).

Decisions for the owner

Each with the recommendation, which the step took on 2026-11-19. The roadmap’s row no longer says the area is grouped with the guide.

  • Which parts follow: those the guide crosses. The roadmap’s row planned an area grouped with the guide. A traced picture is hundreds of shapes in one layer, and a person can’t easily group one of them, and in VectorCraft a guide in that layer is already grouped with all of them. The other choices are the parts wholly inside the guide’s stroke, read as a mark’s band, which leaves out the large parts whose rows show most, and the parts of the shapes grouped with it. Recommended: the parts it crosses, drawn over the picture as a mark is.
  • One name, stitch:guide. VectorCraft documents already name a guide so. The other choice is a name of its own, such as stitch:rows, which would keep the 2 readings apart but gives a person 2 names for one idea. Recommended: one name, with both readings.
  • The guide drawn last steers a part that 2 cross. The other choices, the guide nearest the part’s middle or the one with the longest stretch inside it, are guesses a person can’t see. Recommended: the last drawn.
  • Columns and running stitches keep their stitches. The other choice sews a crossed part no wider than a satin column as a guided fill too. A column’s stitches already follow its form. Recommended: keep them.
  • No setting, the guided fill’s defaults. The guide is enough, as the row says. A person who wants other rows gives the shape its own effect, as for any shape. Recommended: no setting.
  • The rest of a photo may sew in another order, as for marks. Each element a guide makes is a shape more to order. Recommended: accept it, and let M13.35’s cap bound the thickness.

What isn’t built

  • A guide that steers satin columns. Their stitches already lie across the part’s width.
  • A guide with an area, which would steer only the parts inside it, or a guide’s stroke read as a band. The prototype’s guides did their work without them.
  • Turning the base layer to follow a guided fill.

Names of shapes

A traced photo has hundreds of shapes, and every manual control starts with the same question: which shape is this? A mark (marks that keep parts), a guide (M13.24) and a shape’s own effect all need the person to find the shape in VectorCraft. Today a notice names a shape by its element id, vc:63:fill, which is the number VectorCraft keeps in the file. The Layers panel never shows that number. Roadmap step M13.25 gives each shape of a traced design a name that the Layers panel, the notices and the report all show (REQ-AUTO-125 to REQ-AUTO-127, REQ-VC-033, REQ-CLI-023), and says when a path’s own Auto effect replaces its group’s (REQ-VC-034, SC-W0920). The engine’s names module builds the names.

What VectorCraft shows

Read in VectorCraft’s source at 3f8d7a0, its .vectorcraft format and the Layers panel’s code. The app’s window wasn’t run: VectorCraft isn’t built here.

  • A row shows the object’s name. A node of a .vectorcraft document has an optional name. The Layers panel shows Node::display_name() (crates/doc): the name when there is one, else the kind in angle brackets, <Compound Path>, <Path> or <Group>. In a traced document no node has a name. It is a layer with one group in it, and in the group a compound path or a path for each shape. So a traced photo shows hundreds of rows that read <Compound Path>.
  • Search All finds by name. The panel’s search keeps the rows whose shown name, in lower case, contains what the person typed (list_rows in crates/ui-egui/src/panels/layers.rs). A name written into the file is what a person can search for. A query matches inside longer names, so red fill 1 also finds red fill 12.
  • A long name is cut at the row’s end. The panel paints the name clipped to the row, which loses its right end on a narrow panel. VectorCraft keeps at most 255 characters of a name.
  • A name stays a name. StitchCraft’s reader gives an element its node’s name already (Element::name), and a name that begins with stitch: is a marker. A name StitchCraft writes must never begin with it.

Not checked without the app’s window: how many characters fit a row at the panel’s default width, and whether a person can read the names at the panel’s smallest row size.

The parts of a name

A name tells a person the thread, how the shape sews and which one of them it is: Red fill (3), Deep Gold column (1), Black line (12).

  • The thread is the thread’s name. A traced shape’s colour is one of the machine’s threads exactly, since the trace uses the library’s colours as they are, so its name is the palette’s name of that colour. A colour that no thread of the palette has is written as its hex code, #7d6f00.
  • How it sews is the way the shape’s main part sews: the part that keeps the id of its lowest element, which is an area’s fill, or its first narrow part when nothing of it is filled, or a stroke’s first column. A shape none of whose parts keeps that id goes by its first part in the sewing order. A fill of any method is fill, a satin column is column, and a running stitch or another stroke is line. A shape that sews nothing is left out, as the background the design leaves out is (SC-W0906), and so is one merged whole into its neighbours.
  • The number counts the shapes of that thread and that way of sewing in the Layers panel’s order, from its top row, 1 first. The top row is the object drawn last. The number is written in brackets, so that a search for fill (1) doesn’t also find fill (12).
  • A shape is what the elements of one object make. Their ids differ only in their last part (vc:6:fill and vc:6:stroke are of vc:6), and the parts digitizing makes of them add # or ~ and more to an element’s id (vc:6:fill#2). A part has its shape’s name.

The longest name on the pictures measured was 18 characters with a hex code in place of the thread’s name, and the longest thread name of the machine’s palette has 15 (Wisteria Violet). A name then fits in 27.

Where it sews. A name doesn’t say where the shape is in the sewing order. The order is chosen again at every plan, and one small edit moves many shapes in it, as the measures below show. So the report lists the shapes in their sewing order at each plan, each with its place, which the name doesn’t give.

A path’s own Auto effect inside an automatic group

A group’s Auto effect makes everything inside it automatic with its settings. A path inside with an Auto effect of its own sews by its own settings alone (REQ-VC-016), since the nearest effects say how a path sews. VectorCraft writes an effect with every parameter, its defaults included (merged_params in its crates/effects, read at 3f8d7a0), so the path’s own effect stores every setting, and the reader can’t tell a setting the person chose from one left at its default. The group’s settings can’t be merged under the path’s.

The roadmap row said this happens without a word. A case showed that SC-W0807 said it, in the words for StitchCraft effects that reach a path from 2 levels: “it is sewn as the nearest say”. A person learns from them neither which of the group’s settings the path loses nor which path it is, since an unnamed path is only “the object” with its id. The warning SC-W0920 is said in place of SC-W0807 where an Auto effect lies inside an automatic group, with the path’s name and both values of every group setting that the path’s own effect sets otherwise, leaving out those the group keeps at their defaults (REQ-VC-034). The stitches stay as they are today.

Decisions taken

The owner took the 6 recommendations of phase 1 on 2026-11-19:

  • Names are written once, at the trace, and kept as the shapes’ own names. Names made again at every plan would follow the sewing order and change for many shapes after each edit.
  • The number counts in the Layers panel’s order, and the report gives the place in the sewing order beside the name.
  • The number stands in brackets, so that a search finds one shape.
  • The shapes left out are named too, as left out, since notices name the background.
  • The layers keep their order. Automatic digitizing cuts an area away under the areas over it in the layers, and the layers’ order is part of the design.
  • A new code, SC-W0920, says that an Auto effect inside an automatic group replaces the group’s settings, so that stitch explain can say what to do.

What isn’t built

  • SC-I0916 and SC-I0918 don’t name the shapes whose parts a mark keeps or a guide steers. The marks and the guides count the parts in digitizing, before the shapes have names.
  • The VectorCraft plug-in’s previews don’t show names. A document opened in VectorCraft has the names --traced wrote, and a path the person draws later has a name for each plan only.
  • VectorCraft’s own Layers panel isn’t changed.

Pictures from the command line

stitch plan picture.png and stitch export picture.png trace the picture with VectorCraft’s command line, as spike M13.9 decided (ADR-0015) and M13.10 built (REQ-CLI-012, REQ-CLI-013). A design whose extension is .png, .jpg or .jpeg, in any case, is a picture. VectorCraft publishes vectorcraft-cli with each release, and stitch runs the one --vectorcraft-cli names, or else the one on the PATH:

vectorcraft-cli run --commands - --export FOLDER/traced.vectorcraft

It gives it 4 steps on standard input, where a picture of any size fits. They are the compatibility gate’s trace case’s:

  1. swatch.library.load loads the threads stitch palette writes for the machine as a swatch library.
  2. file.place places the picture’s bytes, fitted inside a square --size millimetres across, or else inside the machine’s hoop 0.5 mm in from each side, its aspect kept.
  3. imageTrace.make traces it in colour with the library’s colours as they are, at most --colours of them, by the Abutting method, so that the shapes share their edges.
  4. imageTrace.expand keeps the paths, without the picture.

VectorCraft saves the document into a folder of the command’s own beside the machine file, named as stitch’s temporary files are, and the folder is removed once the document is read. It runs with VECTORCRAFT_NO_PREFS set, so that it neither reads nor writes the user’s VectorCraft preferences, and a picture traces the same for everyone. The document is then the design. It is read with --auto, planned for the machine --profile names or else the reference machine, and named after the picture. --traced writes it beside the machine file, to correct the trace in VectorCraft. A bug-report bundle keeps it too, so that a replay doesn’t need VectorCraft.

The picture’s size. VectorCraft places a picture at its own resolution, or 72 pixels to the inch when its file says none, so a logo a few hundred pixels across would sew larger than any hoop. stitch fits the picture into the machine’s hoop unless --size gives the length of its longer side. The size is the picture’s, its background included, and the shapes left once the background is out sew smaller. Fitted to the hoop, the picture keeps 0.5 mm from each side: a shape along its edge sews as a satin column, whose stitches reach 0.4 mm past its rails, its pull compensation, from rails that may lie up to the tolerance shapes meet within outside the shape. Fitted to the hoop itself, a picture whose shapes reach its sides would sew past the hoop, which SC-E0701 refuses.

How many colours. Image Trace keeps at most --colours of the library’s colours, 6 unless it says otherwise, as in its own panel. The count takes in the background’s colour. A picture with smooth edges, or a JPEG file, has colours between its shapes’ colours, which may trace as threads of their own. A --colours equal to the number of colours the picture has keeps them out. A badge in 3 colours on white traces in 4.

When VectorCraft can’t trace. A command line that can’t be started, missing from the PATH or from the path named, is SC-E0815, which says how to install it, or to trace the picture in VectorCraft. One that fails or doesn’t save the document is SC-E0816, which ends with what it said. Then nothing is written but the report.

StitchCraft traces nothing itself. A tracer of its own would repeat VectorCraft’s, which a harness measures. It would also trace a picture otherwise than VectorCraft does, and the command line would then sew it unlike the tutorial’s flow.

Subject cut-out

A photo’s background traces into shapes of its own, such as turf, a fence or tyres behind a dog. The background rule leaves out one shape, the lowest, when it lies behind everything (Neighbours). So --subject cuts a picture’s subject out before VectorCraft traces it, as spike M13.13 decided (ADR-0019) and M13.14 built (REQ-CLI-014 to REQ-CLI-019). It is off by default, and a picture given without it is traced as above.

The steps. With --subject, stitch changes the picture before the 4 steps VectorCraft takes, in stitchcraft-cutout:

  1. It decodes the picture as its file stores the pixels, with the image crate, as VectorCraft decodes it: a PNG or JPEG file by what its bytes say, at most 16,384 px on a side and 50 megapixels in all.
  2. It finds the subject’s box. --subject-box X0,Y0,X1,Y1 gives it in the picture’s pixels. Otherwise U²-Net-p maps how likely each pixel is to belong to the main subject, at 320 × 320 px, the picture squeezed to that square by Lanczos’s filter and normalized as rembg normalizes it. The map is stretched to run from 0 to 1, and its values of a half or more fall into pieces of pixels that touch, corners included. The box is the one round the piece with the most of the map in it, scaled back to the picture.
  3. MobileSAM cuts the subject out of the box, with input and output prepared as SAM’s own code prepares them. The encoder takes the picture once, the longer side scaled to 1,024 px, each side rounded to a whole pixel, normalized and padded with zeros to a square. Its decoder takes the points of --subject-point, labelled 1, and of --not-subject, labelled 0, then the box’s 2 corners, labelled 2 and 3, each scaled as the picture’s side along it is. It gives a map of 256 × 256 logits across the square, which is scaled to the square, cut to the picture’s part of it and scaled to the picture, each time bilinearly between the pixels’ middles. The logistic function of each value, times 255, is the pixel’s alpha, or the picture’s own where that is lower.
  4. The picture with that alpha, cropped to the box round the pixels of an alpha of 128 or more, is written as a PNG file. file.place places it where it would place the picture, so --size and the hoop fit the subject.

Image Trace leaves out the pixels whose alpha is under 128, and gives a pixel on the cut edge the colour beside it (VectorCraft’s crates/trace at 3f8d7a0). The trace then contains the subject alone, with no background for the background rule to find. If MobileSAM keeps none of the pixels, or if U²-Net-p’s map has no piece above a half and no box is given, SC-E1202 says so and suggests --subject-box. A picture the cut-out can’t read is SC-E1203. stitch then writes the report alone, as when VectorCraft can’t trace. Every loop over the picture charges the budget, which runs out with SC-E0004. A cut-out made says the box it came from, how much of the picture it kept and its size (SC-I1206), and the report keeps it all.

Correcting a cut-out. A cut-out is wrong when the box contains more than the subject and MobileSAM keeps it, or when MobileSAM keeps less than the subject. --not-subject X,Y marks a point of what isn’t the subject, and --subject-point X,Y a point of what is, each as often as needed and in the picture’s pixels. The decoder takes the points with the box, U²-Net-p’s when the user gives none, since a point without a box can lose much of the subject. A box without area or one that extends past the picture, a point outside it, and any of these options or --cutout without --subject are usage errors, and so is --subject for a design that isn’t a picture. --cutout FILE writes the cut-out beside the machine file, with the other files asked for, all or none, so that the user can see what was kept.

In VectorCraft. A filter can’t read or replace a placed image, and a plug-in couldn’t run the models within its budget (ADR-0019, decision 2). stitch cutout PICTURE -o FILE writes the cut-out alone, with the same marks, and says what it kept as stitch plan does. The user places it where they would place the photo, and traces it with Image Trace as the tutorial does. A picture whose background another program made transparent traces as its subject too, without --subject. The owner’s traced dogs were made so (M13.15, docs/fixtures/README.md › The traced dogs).
